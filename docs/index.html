Zero 2 Terminal · GPL-3.0 · Android 10+

A terminal for Android that is also a way to drive Android.

Z2Term runs Alpine / Ubuntu / Arch / Kali without root, opens a Linux desktop in a tab, and lets the shell reach the phone itself — read a notification, ask you a question in the notification shade, or run a script when the battery, the network or an incoming SMS changes.

Three things it does that a terminal usually doesn't

Everything below is in the one APK. No companion app, no setup script.

01A distribution, immediately

Install the APK and apk / apt / pacman work. The default execution engine, z2root, is a ptrace-based userspace implementation written for this app — no root, no kernel module. PRoot and chroot are also selectable.

02The shell talks to Android

Around 20 z2-* helpers: notifications, clipboard, sensors, torch, intents, alarms, text-to-speech, and wireless adb to the device itself. z2-ask puts a question in the notification shade and reads your reply into a shell variable.

03Automation that outlives the app

z2-when fires scripts on device events — charging, battery level, time or cron, Wi-Fi, connectivity, boot, a share from another app, an incoming SMS, sensors, an arriving notification, a new file. Rules are plain text and survive reboots unopened.

04A Linux desktop in a tab

Xvnc and openbox with an RFB client built into the app, with audio and video. z2gui starts the desktop; z2run <app> launches a GUI program and opens the tab for you.

05Japanese, properly

A built-in kana-kanji IME with prediction and frequency/recency learning, plus a custom on-screen keyboard. It can be enabled as an OS-wide input method, and your own words load from a file.

06SSH both ways

SSH and SFTP client with keys held by the Android Keystore, port forwarding that keeps running after the tab closes, and a built-in sshd bound to localhost by default.

07Servers that stay up

Register any start command under Settings → Resident servers and it keeps running in the background — without the app being open. Host a small web server, a sync daemon or a bot from your phone; the Status widget shows how many are up, and restarts on boot are handled.

What it looks like to use

# ask, from the notification shade
name=$(z2-ask "Branch name?") \
  || echo "cancelled"

# run a script on a device event
z2-when charge:start run ~/sync.sh
z2-when net:online if=ssid=Home \
  cooldown=1h run ~/backup.sh
# a Linux desktop, from the shell
z2gui
z2run firefox

# why isn't it working?
z2doctor --clip

# the device's own adb, no PC
z2adb shell getprop ro.product.model

Why another terminal app?

Termux is the right answer if you want the largest package repository and the most battle-tested tooling. Z2Term is built around a different question: what if the terminal were a first-class way to operate the phone, and it all came in one APK?

Z2TermTermux + its add-ons
Linux distributionAlpine bundled, ready on first launch; Ubuntu / Arch / Kali installableA package installs one
Linux GUIBuilt-in GUI tab (Xvnc + RFB client), audio and videoA separate X11 or VNC viewer app
Drive Android from the shellBuilt in — ~20 z2-* helpersA separate companion app
Event-driven automationBuilt in — z2-when, with a tab, run logs and a kill switchA separate companion app, usually paired with a third-party automation app
Japanese inputBuilt-in IME, also selectable OS-wideThe OS keyboard
SSH / SFTP and sshdBuilt in, keys in the Android KeystoreInstall the packages yourself
DistributionGitHub ReleasesF-Droid and its own repository

Both are GPL-3.0 and neither collects telemetry. If you already have a Termux setup you are happy with, Z2Term's reason to exist is rows two, three and four.

Download

Two APKs ship with every release. Tap the file on your device and allow installing from an unknown source.

FileContentsWhich to pick
app-foss-release.apkNo prebuilts (~21 MB)The recommended one. 9× smaller, and each update downloads ~21 MB instead of ~190 MB — nice on metered data or slow links — and it carries no third-party prebuilts. Alpine is fetched once, verified by SHA-256; updates never re-download it
app-full-release.apkPRoot and the Alpine rootfs bundled (~190 MB)When you want it offline from the very first launch. The distribution is inside, so nothing downloads — at the cost of ~190 MB for the app and for every update

Same app either way; the only difference is whether Alpine is downloaded once on first launch. Automatic updates don't shrink the download — every update fetches the whole APK — so the size gap keeps paying off.
