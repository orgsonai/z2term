## 1. 最重要の制約（これを誤ると詰む）

- **proot / libproot_loader / libtalloc は `nativeLibraryDir` に置かないと動かない**。
  - 根拠: `proot/ProotLauncher.kt` が `File(nativeLibraryDir, "libproot.so")` / `"libproot_loader.so"` / `"libtalloc.so"` を直接 execve・参照する。無いと `PRoot binary not found` で `/system/bin/sh` フォールバック。
  - Android API29+ は**アプリ data 領域からのバイナリ execve を W^X/SELinux でブロック**する。`nativeLibraryDir` はインストーラ管理の読み取り専用領域で、ここからの実行だけが許される。
  - 帰結: **proot を実行時ダウンロードして動かすことはできない**。proot/talloc は **APK 同梱必須**。
- **したがって「外部ライセンス表記を完全にゼロ」にはできない**。proot(GPL-2.0) と talloc(LGPL-3.0) の表記は残る。
  - rootfs を外せるかどうかが分かれ目。rootfs(Alpine の全パッケージ群)が外部表記の大半なので、**rootfs を外すのが本作業の主目的**。

## 3. 作業手順 ※フェーズ1で全て実施済（記録として保持。フェーズ2では §5 を見る）

### 3-2. foss で Alpine を実行時ダウンロードできるようにする

- 現状 Alpine は「同梱（assets 直読み）」前提（`distro/DistroSpec.kt` / `DistroBundle` / `DistroInstaller.isDistroReady`、DESIGN-SPEC §4.4）。Ubuntu/Arch/Kali は既に `DistroDownloader` で実行時 DL（SHA-256 検証）している。
- やること:
  1. `DistroSpec` の Alpine に **ダウンロード URL + SHA-256** を持たせる（Alpine 公式 CDN の `alpine-minirootfs-<ver>-aarch64.tar.gz`）。
  2. **フレーバーで分岐**: `BuildConfig.IS_FOSS` のとき Alpine も「非同梱＝DL 対象」として扱う（full は従来どおり assets から展開）。`DistroBundle.BUNDLED_DISTRO_ID` / `isDistroReady` の assets 前提を foss で迂回。
  3. foss は**初回オフライン起動不可**になる（DL 必須）。`TerminalSession` の起動シーケンスで「proot はある／rootfs は未取得 → DL」へ素直に流れるか確認。
- 注意: full の挙動（オフラインで即 Alpine）は**変えない**。差はあくまで foss 側だけ。

### 3-3. ライセンス表記を実態に合わせる（`legal/OssComponents.kt`）

- rootfs を foss から外したので、**rootfs（Alpine パッケージ群）のエントリは foss で隠してよい**（= `onlyFullFlavor` のままで正しくなる）。
- 一方 **proot / talloc は foss でも同梱継続**なので、`onlyFullFlavor` を外して**両フレーバーで表示**する（配布している以上、告知必須）。

## 5. フェーズ2: proot 自前実装（外部表記の完全ゼロ化・長旅）

フェーズ1完了後の長期課題。**proot(GPL-2.0) + talloc(LGPL-3.0) を自分のコード（GPL-3.0）で置き換える**と、外部バイナリの同梱がゼロになり、外部ライセンス表記を完全に消せる。唯一「完全ゼロ」に到達する道。

### 5-1. proot が実際にやっていること（置き換え対象）
- `ptrace(PTRACE_TRACEME / PTRACE_SYSCALL)` で子プロセスの **syscall を傍受**し、引数のパスを書き換える（rootfs を `/` に見せる chroot 相当 / bind マウント相当）。
- fakeroot 的な uid/gid 偽装、`execve` のローダ差し替え（`libproot_loader`）、`/proc` 等の見せ方調整。
- talloc は proot 内部の**メモリ管理ライブラリ**にすぎない。自前実装すれば talloc 依存ごと消える。

### 5-2. 実装方針（案）
- 言語: C/C++（JNI、既存 `cpp/` に同居）。ptrace は NDK から叩ける。自前 `.so` を `nativeLibraryDir` に置く（実行制約は proot と同じ＝ §1 の W^X 前提は変わらない。**自前実装でも APK 同梱は必要**だが、それは自分のコードなので外部表記は出ない）。
- 最小機能から順に: (a) `PTRACE_SYSCALL` ループ + (b) `openat`/`stat`/`execve` 等のパス書き換え + (c) rootfs を `-r` 相当でルート化 + (d) `/dev /proc /sys` の bind 相当。SSH/GUI は後回し。
- arm64-v8a のみ（既存方針どおり）。seccomp(`PTRACE_SECCOMP`)による高速化は将来課題。
- 既存 `proot/ProotLauncher.kt` の起動インターフェース（`launch(...)` / `nativeLibraryDir` のバイナリ名）を**そのまま流用**し、エンジン実体だけ差し替えられる形にする。

### 5-3. 段階移行（壊さず進める）
1. 自前エンジンを**ビルドフラグ/裏設定**の裏で proot と並走させ、同一 rootfs で `apk`/`apt`・SSH・GUI が動くか動作比較。
2. 互換が取れたら foss の既定エンジンを自前実装へ切替、proot/talloc を APK から除去。
3. `legal/OssComponents.kt` から proot/talloc を削除。OFL フォントを残すなら表記は OFL のみ、フォントも自作/不要化すれば**外部表記ゼロ**達成。
4. **full は §0 のとおり proot 同梱のまま据え置き**（自前エンジンが十分枯れたら full 移行も検討可だが急がない）。

### 5-4. リスク / 心構え
- proot は ptrace syscall 傍受の塊で**実装難度が非常に高い**（長旅）。完成まで foss は proot のままでよい＝フェーズ1の状態で運用継続。
- Android/SELinux 下の ptrace 制約、execve ローダの扱いが地雷。**小さく作って実機で逐次検証**（uninstall せず動作確認するユーザー方針）。
- 「完全ゼロ」は **5-3 の (3) まで到達して初めて**達成。それまでは外部表記（proot/talloc）が残る前提で運用する。

  - `canonicalize_guest()`: ゲスト絶対パスを**コンポーネント単位で走査**し、各要素を rootfs 内で `readlink` して symlink を逐次展開（絶対 symlink はルートから／相対 symlink は親基準）、`.`/`..` も畳む。`deref_final` で最終要素を辿るか分岐（open/stat=辿る、lstat/unlinkat/readlinkat/新規作成名=辿らない）。これで openat 等に渡るホストパスが symlink を一切含まなくなる。

  - **真因**: fresh の `claude` 起動が即 `Error: Can't access working directory /data/data/com.zerotoship.z2term/files/shared_home: Path ... does not exist` で終了。切り分け＝`node -e process.cwd()`(=`getcwd` syscall)は**正しく `/root` を返す**(逆変換済)が、`readlink /proc/self/cwd` は**ホスト実パス `/data/.../shared_home` を未変換のまま返す**。claude(Bun) は cwd を **`readlinkat(/proc/self/cwd)` で解決**するためホスト実パスを掴み、rootfs 内に存在しないと判断して**ロゴも出さず即終了**＝ユーザーの「立ち上がらない」症状そのもの。エラー文字列が `readlink` 出力と完全一致。
  - **修正**: z2root.c に **`readlinkat`(78) の戻りバッファ逆変換**を実装（`rewrite_readlink_result`）。`getcwd`(17) と同じ `host_to_guest()` で、`/proc/self/cwd`・`/proc/<pid>/cwd`・`/proc/self/exe`・`root` 等 magic symlink が返すホスト実パスをゲストパスへ戻す（proot 同等挙動）。`syscall_needs_exit` に 78 を追加、entry で buf=regs[2]/bufsiz=regs[3] を控え、exit で `ret` バイトを読み NUL 補完→逆変換→書き戻し＋`regs[0]` を新長へ更新。相対リンク先・rootfs/bind 外のリンク先は無変換（getcwd と同じ no-op 条件）。NDK29 で `libz2root.so` ビルド済。
  - **次手（ユーザー操作・本丸の最終検証）**: 0.8.52-alpha(60) full release を install→再起動→z2root タブで **`claude` がロゴ出て対話起動するか**を確認。直れば確定。**TODO(下記)の「readlinkat 戻り値逆変換未実装」はこれで解消**。
