# Changelog

Changes in each version, newest first.

**1.0.8 (versionCode 706)**: A running command can now be answered in the edge panel's simple terminal. Until now a command's input was empty, so a command that asks y/n, such as `pacman -Syu`, ended there. While a command runs, the input row answers it and the button reads Send (an empty row sends Enter). Stop now ends only the running command and keeps the shell (the directory you changed to and your variables stay; ↻ still resets everything). Progress displays that used to pile up into one endless line now replace their line. The terminal width follows the result view, and pagers are not used, so `git log` and `man` no longer stop waiting for a key. When a password is asked for, it does not appear in the result, but the characters are visible in the input row while you type. Programs that read single keys or run full-screen still belong in a regular terminal tab.

**1.0.7 (versionCode 705)**: Removed the card at the top of the QR guide (Settings › Maintenance › "Show a guide" › `qr`) that told you to install `qrencode`. The app has made QR codes itself since 0.8.630, so nothing needs installing inside a z2term tab.

**1.0.6 (versionCode 704)**: What a guide added can now be put back when you decide not to use it. Each row under Settings › Maintenance › "Show a guide" has "Clean up" at its right end. It shows the steps that remove the macro, automation rules, panels and tile slots that guide added, on the same kind of cards as the guide. Nothing is removed until you tap a card, and ✕ keeps whatever you want to keep. What you entered yourself, such as the feed list or the reminder records, is on a separate card. Also added `z2-macro remove <name>`, which deletes your copy of a bundled sample (it stops without deleting a copy you edited). The Tips in Settings now mention that double-tapping text in the terminal selects a word.

**1.0.5 (versionCode 703)**: Added "Z2 Mono" to the terminal fonts. It is a monospaced font made for this app and covers Latin letters, digits and symbols (Japanese and other scripts are drawn with the system font as before). Pick it under "Font family" in Settings. It ships in both the GitHub APK and the F-Droid build.

**1.0.4 (versionCode 702)**: The three terminal fonts (IBM Plex Mono, JetBrains Mono, Fira Code) now ship in the F-Droid build as well. Until now the F-Droid build had none of them and offered only the system font. On some devices the system font leaves a wide gap after every character; these three are now available there too. The GitHub APK is unchanged.

**1.0.3 (versionCode 701)**: The built-in keyboard has a new face for typing Japanese in romaji (`a` → あ, `ke` → け, `kyou` → きょう). Turn on "Japanese — romaji" in the face list under ⚙ Settings › Keyboard, input and reach it with the switch key (あa); it starts off. It is the letter face without TAB, ⇧, CTRL and ALT, which makes the letter keys a little over 10% wider. The letters and ESC, ⌫, ⏎ and the arrows sit where they do on the letter face. The right end of the fourth row is `、 。 ー`, and the space key converts while something is being composed and types a space otherwise. Conversion, candidates and learning are the same as on the flick kana face.

**1.0.2 (versionCode 700)**: Emoticons and ASCII art you added now have a list of their own. ⚙ Settings › Keyboard, input › "Your own emoticons and ASCII art" keeps just the input field and a count; press "Manage list" to open the list. There you can search, remove entries one by one or remove everything, and long art is folded to 6 lines (tap to show all of it). Until now every entry was listed inside Settings, pushing the other items down as the list grew. Also, Japanese input from an external keyboard (toggled with the half/full-width key, Shift + Space and so on) now works only when the app language is Japanese or you have turned the kana face on yourself. If you do not use Japanese, Shift + Space no longer switches to kana.

**1.0.1 (versionCode 699)**: Each pane title in the split view now has an expand button at its right end. Press it to go back to one pane showing just that tab (the same as double-tapping the title, without long-pressing the GUI button and choosing "One pane"). **0.8.639-alpha (versionCode 647) — built and verified on device**: On the hidden "chroot" engine, installing a package always failed with `not enough free disk space` even with plenty of space free. Read from inside the chroot, `/proc/self/mounts` has **no line for `/` at all**: the Android root lies outside the chroot and the rootfs itself is not a mount point. `/etc/mtab` is a symlink to that file, so anything asking "which filesystem am I on" gets it wrong — pacman could not determine the cachedir's mount point and aborted. The rootfs is now **bind-mounted onto itself** so it appears as `/` (the standard way to prepare a chroot). Verified on device: `pacman -Sy` installs to completion, and sshd starts inside the chroot (host keys generated, then a safe stop because no authorized_keys is set).

**0.8.638-alpha (versionCode 646) — built and verified on device**: The hidden "chroot" execution engine on rooted devices always died with `[process exited]` the moment a tab opened. The cause was the `TZ` value embedded unquoted into the chroot bootstrap script. A POSIX `TZ` writes the abbreviation as `<+09>`, so the shell read `<` as an input redirection and the script died (`can't open +09`) before ever reaching the line that runs `chroot`. The z2root path passes the environment directly and never goes through a shell, so only the chroot path was affected. Verified on a rooted device (Magisk, SELinux Enforcing): real-root chroot startup, the full set of bind mounts, job control, the `z2-*` commands, and the clock inside the distro.
