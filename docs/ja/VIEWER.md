# マクロから使うビューとフォーム

0.8.640-alpha（versionCode 648）。アプリが提供するのは、ローカルHTMLの表示、汎用フォーム、登録した操作をマクロへ渡す仕組みです。RSSの取得・記事管理、予定の保存・日時解釈・予約・削除などの用途固有の処理はマクロ側に置きます。利用者が新しいマクロを作る際に、アプリの改修は必要ありません。

検証（0.8.641）: デスクトップで `assembleRelease`、関連ユニットテスト133件、`lintDebug`（エラー0件）が成功しました。Android実機でタッチ配送・表示設定・汎用フォームのテスト7件も成功しました。タッチ配送テストは組み立てたビューへイベントを送る方式で、実際のパネルを指で操作する確認は未実施です。

## エッジパネルに表示する

1. エッジパネルの「⚙」を押します。見えない場合は、パネルを開いたままパネル外の余白を長押しします。
2. 「配置」→「自由な枠を追加（マクロ・コマンド）」を開きます。
3. 部品を「表示」、動作を「ビュー（z2-view）」にします。0.8.640では部品名が「文字表示」です。
4. 表示名を付け、「実行するコマンド」にHTMLを生成して `z2-view` を呼ぶマクロを指定します。対応版を導入済みなら `rss.sh view` または `remind.sh view`、自分のHTMLなら `z2-view "$HOME/page.html"` です（HTMLファイルは事前に用意）。
5. 「ビューの更新方式」で「手動のみ」か「自動」を選びます。必要なら「表示」で更新・拡大ボタンをOFFにし、「詳細設定」で自動更新間隔や実行時間の上限を指定して、「保存」→「完了」で戻ります。手動のみでは最初に「更新」を押します。

0.8.641以降は、項目編集の「部品の選び方」、選択中の動作の説明、入力欄ごとの例を見ながら設定できます。ビューに限らず、ボタン・入力欄・選択欄・スイッチ・リストも対象です。「この例を入力」は空欄だけに入力し、その場で保存・実行しません。

コマンド内の `z2-view` は別画面を開かず同じ項目へ表示します。既定の「手動のみ」では開いたときにコマンドを実行せず、保存済みの頁を表示します。初回は「更新」を押してください。自動を選んだ場合だけ開くときに実行します。

```sh
z2-edge panel reading handle=bar side=right width=90% height=65% fit=fixed close=on
z2-edge set reading:page type=view 'run=z2-view "$HOME/page.html"'
z2-edge on
```

重ねて表示する許可が未設定なら `z2-edge permission` を先に実行してください。項目がビュー1個だけならパネル内の残りの高さを使います。複数の部品と並べることもできます。項目の幅・高さは既存の配置設定で指定します。

外から既存のビュー項目へ送る場合は、次の形です。パネルは自動で開きません。

```sh
z2-view --edge reading:page "$HOME/page.html" "題名"
```

「拡大」で通常画面へ移り、同じ表示処理・操作定義を使います。スクロール位置は同じプロセス内の開き直しで保持します。頁のキャッシュは項目ごとに独立しています。

`view-refresh=auto every=30` なら開いたときと表示中の30秒ごとに `run=` を実行します。`view-refresh=manual`（0.8.641以降の既定）では、間隔が保存されていても開く・タブ切替・定期更新でコマンドを実行しません。タブ切替・閉じる・消灯で表示用の実行とタイマーを停止します。自動更新と手動の「更新」は次のように使い分けます。

- 自動モードで開いたとき／`every`：項目の `run=` を実行。保存済みデータから頁を作る用途に向きます。
- 手動の「更新」：操作定義に `refresh` があればそのマクロ操作を呼ぶ。なければ `run=`、それもなければキャッシュを読み直します。
- 実行失敗時：前の頁を残し、エラーを表示します。

「表示」の「更新ボタンを表示」「拡大ボタンを表示」で個別に切り替えられます。マクロが定義する追加などの操作ボタンには影響しません。表示するボタンがなければ上部の空行も省きます。手動で更新ボタンを隠した場合でも、外部マクロからの送信や操作後に届く頁は反映します。

| 項目の設定 | 値・既定 |
|---|---|
| `view-refresh` | `manual`（既定）／`auto` |
| `view-refresh-button` | `on`（既定）／`off` |
| `view-expand-button` | `on`（既定）／`off` |
| `view-find-button` | `on`／`off`（既定）。頁内検索のボタン（1.0.15） |
| `view-text-size` | `50`〜`300`（%、既定 `100`）。文字の大きさ。ピンチで変えると自動で入る（1.0.16）。項目の「表示」でも入れられる（1.0.18） |
| `view-pinch` | `text`（既定）／`page`。ピンチで文字の大きさを変えるか、頁ごと拡大するか（1.0.18） |
| `every` | 自動時のみ有効。空欄・0なら開いたときだけ、5〜86400秒なら周期更新も行う |

タブ名の欄は左右にスワイプして横スクロールできます（スワイプだけでは選択タブを変えません）。ビュー本文では左右スワイプで前後のタブへ、上下スワイプで頁内をスクロールします。縦に動かし始めた指のずれや長押しではタブを切り替えません。

## 端末から読む（標準入力・ただの文字）

1.0.15 から、HTML のファイルを作らずにコマンドの出力をそのまま読めます。

```sh
ls -l | z2-view                 # パイプで渡す（引数なし）
ps -ef | z2-view - "プロセス"       # - は標準入力。2 つ目は題名
z2-view notes.txt               # ただの文字のファイル
```

- 最初に見える文字が `<` でないものは「ただの文字」として扱います。折り返し付きの等幅で表示し、端末の色の指定（エスケープシーケンス）は取り除きます。文字はすべてエスケープするので、タグとしては解釈しません。
- ファイル名が `.html` / `.htm` / `.xhtml` のものは、中身にかかわらず頁として扱います。
- 自動の判定と違う扱いにしたいときは `--text`（必ず文字）／`--html`（必ず頁）を付けます。
- 大きさの上限は頁と同じ 4 MB です。文字として包んだあとの大きさも 4 MB までです。UTF-8 として壊れたバイトは置換文字で表示します。

## 頁内検索

1.0.15 から、表示中の頁の中で語を探せます。「検索」を押すと上に入力欄が出て、打つたびに一致した箇所へ色が付き、件数（`3/12` のように今の位置と総数）が出ます。▲▼で前後の一致へ移動し、✕で閉じます。キーボードの検索キーでも次の一致へ進みます。

- 通常画面（端末から `z2-view` で開いた画面と「拡大」した画面）には常に「検索」が出ます。1.0.19 から、端末から開くときに `--no-find` を付けると出しません（「更新」は `--no-refresh`）。
- エッジパネルのビュー項目では既定で出しません。項目の「表示」で「「検索」ボタンを表示」を ON にするか、`view-find-button=on` を指定します。
- 検索中に頁が更新されても、同じ語で探し直します。フォームを開くと検索は閉じます。

## 文字の大きさ（ピンチ）

1.0.16 から、ビューの本文を 2 本指でピンチすると文字の大きさが変わります（50〜300%）。頁全体を絵として拡大するのではなく、文字が大きく／小さくなって幅に合わせて折り返し直すので、横にはみ出しません。

- 端末から `z2-view` で開いた画面（「拡大」した画面を含む）は、大きさを 1 つ覚えて次に開く頁にも使います。
- エッジパネルのビュー項目は、項目ごとに覚えます（`view-text-size`）。

文字の大きさを `px` で決めた頁も同じ割合で変わります。

### 頁ごと拡大する・文字の大きさを決める（1.0.18）

ピンチで文字ではなく**頁そのもの**を拡大・縮小することもできます。絵や表のように、折り返すと崩れる頁に向いています。拡大すると頁が幅からはみ出すので、指で上下左右に動かして読みます。

- 端末から開く画面は、`z2-view` に付けて選びます。開くたびに決めます。

  ```sh
  z2-view --pinch page page.html          # ピンチで頁ごと拡大
  z2-view --text-size 130 page.html       # この頁の文字の大きさを 130% で開く
  ```

  `--pinch text`（既定）は 1.0.16 と同じ動きです。`--text-size` は 50〜300 で、付けたときはこの頁だけその大きさで開きます（付けなければ覚えている大きさ）。どちらもパネルへ送るとき（`--edge` やパネルの中のコマンド）は効かず、項目の設定に従います。
- エッジパネルのビュー項目は、項目の「表示」で「ピンチの動き」（文字の大きさを変える／頁ごと拡大する）と「文字の大きさ（%）」を選びます（`view-pinch=page`、`view-text-size=130`）。「拡大」で全画面に移ったときも、項目のピンチの動きを引き継ぎます。
- 頁ごと拡大しているときも、文字の大きさの指定は効きます。頁の拡大率は覚えません（開くたびに幅に合わせた大きさから始まります）。
- パネルでは、拡大した頁が横へ動けるあいだは左右に動かすと頁が動き、端まで来るとタブが切り替わります。

## 頁の既定の色（1.0.19）

頁が文字色を決めていないときは、端末のテーマの文字色で出します（リンクはテーマの強調色）。これまでは黒い文字のままで、暗いテーマでは背景と同じ色になって読めませんでした。頁が `color` を決めていれば、そちらが優先されます。背景だけを明るい色に決めた頁は、文字色も合わせて決めてください（テーマが暗いと、明るい背景に明るい文字になります）。

## 全画面を閉じる（1.0.23）

上端の題名の行を押すと閉じます。見た目はアプリの設定画面の上のバーと同じで、左端の ← は目印です。行のどこを押しても同じです（1.0.24）（Android の「戻る」でも閉じます）。フォームを書きかけのときは、破棄してよいかを確かめてから閉じます。この行はいつも出ていて、消すオプションはありません。

## 全画面のボタンを消す（1.0.19）

端末から開く画面には「更新」と「検索」が最初から出ます。要らなければ `z2-view` に付けて消します。

```sh
z2-view --no-refresh page.html            # 「更新」を出さない
z2-view --no-refresh --no-find page.html  # どちらも出さない
```

パネルのビュー項目は、これまでどおり項目の「表示」で選びます。

## マクロがフォームと操作を定義する

HTMLとは別のJSONを明示して読み込ませます。

```sh
z2-view --controls "$HOME/controls.json" "$HOME/page.html" "自作の画面"
```

```json
{
  "handler": "example.sh",
  "refresh": ["view"],
  "actions": [
    {
      "id": "save",
      "label": "保存",
      "toolbar": true,
      "args": ["save"],
      "fields": [
        {"label": "内容", "type": "text"},
        {"label": "日時", "type": "datetime"},
        {"label": "分類", "type": "choice", "choices": [
          {"value": "personal", "label": "個人"},
          {"value": "work", "label": "仕事"}
        ]}
      ]
    },
    {"id": "remove", "label": "削除", "args": ["remove"], "param": true, "confirm": "この項目を削除しますか？"}
  ]
}
```

`handler` は利用者が導入した `$HOME/.z2term/macros/` 内の `.sh` のファイル名です。パスやシェル式は指定できません。例の保存を押すと、`example.sh` に `save`、内容、日時、分類が**別々の引数として**渡ります。空白・改行・引用符も値のまま扱い、シェルコードとして再解釈しません。マクロ側でも `"$2"` のように引用し、`eval` は使わないでください。

| 設定 | 意味 |
|---|---|
| `refresh` | 手動更新時にhandlerへ渡す固定引数の配列。省略可 |
| `actions[].id` | 操作ID。英数字・`_`・`-`、1〜80文字、同じ頁で一意 |
| `label` | ボタン・フォームの表示名 |
| `args` | 操作時の固定引数。入力値はその後へ欄の順に追加 |
| `toolbar` | `true` ならビュー上部にボタンを表示 |
| `confirm` | 実行前に表示する確認文。省略可 |
| `param` | `true` なら頁のリンクから値を 1 つ受け取る（下記）。`toolbar` とは併用不可（1.0.15） |
| `fields` | 汎用フォームの入力欄。省略時はフォームを出さず操作 |
| `type=text` | 自由入力。`default` で初期値 |
| `type=multiline` | 複数行の自由入力。最初から 4 行分の高さで出す（1.0.15） |
| `type=number` | 数値。数字キーボードを出し、`-12` や `3.5` の形でなければ送信しない（1.0.15） |
| `type=switch` | ON/OFF のスイッチ。値は `on` か `off`。`default` が `on` なら最初から ON（1.0.15） |
| `type=date` | 日付だけの選択。値は `yyyyMMdd`（1.0.15） |
| `type=time` | 時刻だけの選択。値は `HHmm`。省略時の初期値は1時間後（1.0.15） |
| `type=datetime` | 日付・時刻の選択。値は端末の現地時刻 `yyyyMMddHHmm`。省略時の初期値は1時間後 |
| `type=choice` | `choices` の `value` を渡し、`label` を画面に表示。`default` で初期選択 |
| `required` | 既定true。空でもよい欄はfalse |

HTML本文からは `<a href="z2-action:save">保存</a>` のように、別途登録した操作IDだけを呼べます。操作定義がないHTMLでは、これらのリンクから何も実行されません。

`"param": true` の操作は、リンクの `/` のあとに値を 1 つ付けて呼びます（1.0.15）。一覧の各行に「削除」を置くとき、行の数だけ操作を登録する必要がありません（操作は 500 個まで）。

```html
<a href="z2-action:remove/123">削除</a>
<a href="z2-action:remove/456">削除</a>
```

例の `remove` は、`example.sh remove 123` のように、固定引数のあとへ値を**1 つの引数として**渡します。フォームの欄があれば、入力値はさらにそのあとに続きます。値は 1〜4096 文字です。`#` `%` `?` や空白を含む値は URL の書き方でエンコードしてください（`%23` など。アプリが元に戻して渡します）。値の付かないリンクで `param` の操作を呼んだ場合と、`param` でない操作に値を付けた場合は、何も実行しません。確認文は操作ごとに 1 つなので、行ごとに違う確認文を出したいときは、今までどおり行ごとに操作を登録します。

処理後、マクロが再び `z2-view` を呼ぶと同じビューが更新されます。通常画面でもパネルでも同じです。アプリが渡す `Z2_VIEW_SESSION` / `Z2_VIEW_TARGET` を通常は変更する必要はありません。`--edge` を明示すると指定先へ送ります。

同じビューからは実行中の再送信を受け付けません。失敗時は入力を残します。編集中に届いた頁はフォームを閉じてから反映し、未送信のフォームを閉じる際は確認します。**送信済みの操作はパネルを閉じても完了まで続行**します。閉じたビューへの返答が画面を再度開くことはありません。実行上限は項目の `timeout=1〜300` 秒（既定30秒）。タイムアウト前に保存などが済んでいる場合もあるので、マクロ作者は再試行にも配慮してください。

実際に動く汎用例は [`examples/view-form.sh`](../../examples/view-form.sh) です。テキストと分類を保存・消去するだけのマクロで、同じフォームを別用途に使う見本です。`$HOME/.z2term/macros/view-form.sh` へ置いて実行できます。

## 表示と操作の境界

- JavaScript・ネットワーク取得・WebViewからのファイル／contentアクセスは無効。画像は `data:` URIで埋め込みます。
- HTTP(S)リンクは明示的なタップで外部ブラウザへ開きます。
- 操作は現在のJSONに登録されたIDへのタップだけ。HTMLから任意のコマンド文字列を渡せません。
- 外部データをHTMLへ入れる際は、マクロで必ずエスケープします。JSONも文字列を適切にエスケープしてください。
- HTMLはUTF-8で4 MiB、操作定義は256 KiBまで。操作は最大500個、1操作の固定引数は32個、欄は8個、選択肢は32個。表示用stdoutの64 KiB制限とは別のファイル転送です。
- 追加依存、Webサーバー、用途別のアプリ内データベースは不要です。

## 同梱マクロの利用例

APK更新後にローカルの端末タブを開き直してください。既存のマクロのコピーを自動では上書きしません。`z2-macro diff rss` / `z2-macro diff remind` で差分を確認し、自分の変更がなければ `z2-macro install -f rss` / `z2-macro install -f remind` で更新します。

```sh
z2-edge panel reading handle=bar side=right width=90% height=65% fit=fixed tabbar=on close=on
z2-edge set reading:page type=view 'run=rss.sh view' timeout=120
z2-edge tab reading reminders "リマインダー"
z2-edge set reminders:page type=view 'run=remind.sh view' view-refresh=auto every=30
z2-edge on
```

RSSは保存済みの記事を即座に表示し、一覧の画面の中からの操作（「更新」と購読先からの「記事一覧」）のときだけ巡回します（1.0.14。パネルの「更新」は 1 回目から巡回します）。一覧から巡回して新着が見つかっても、最初は通知しません。通知するかどうかは一覧の「設定」で選びます（1.0.21）。記事のリンク先は外部ブラウザです。フィード取得の前提は既存マクロと同じPython 3標準ライブラリです。サムネイル画像（「設定」で選択）を使う場合だけ Pillow が要ります。「購読先」「アーカイブ」「設定」は頁の中のリンクで、パネルの上のボタン列には「更新」「拡大」だけが並びます。

記事一覧の「購読先」からフィード URL を追加・変更・削除できます。変更は次の巡回から反映し、取得済みの記事は残します。「記事一覧」で戻ると新しい購読先を取得します。購読先の画面は `rss.sh feeds` でも開けます。

1.0.15 で、記事ごとの「削除」・購読先の「削除」・アーカイブの月の切り替えを、値付きリンク（`param`）の操作 1 つずつにまとめました。これまで記事の削除は操作数の上限（500）に合わせて新しい順に付けていましたが、一覧のすべての記事に付きます。「設定」の 2 項目はスイッチ（`type=switch`）になりました。

リマインダーのHTMLとフォームJSONはマクロが `sh` / `awk` で作ります。「追加」では内容（複数行の欄。1.0.15）・日時・繰り返しを指定でき、任意の文字入力で既存の日時表現も使えます。文字指定は日付と繰り返し設定より優先します。毎週の場合は選んだ日付の曜日を使います。一覧は「予定」「繰り返し」「通知済み」を区別し、通知済みを完了とは扱いません。各行の削除は固有IDを指定し、予約・繰り返しルール・スヌーズを取り消します。取消失敗時はデータを残します。追加時に必要なイベント受け口を登録し、タイル配置は行いません。通常画面からは `remind.sh view` で同じ操作ができます。
