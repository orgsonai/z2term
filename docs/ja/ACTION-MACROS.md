# Android操作マクロ

作業版 0.8.592-alpha / versionCode 600。**ビルド・単体テスト検証済み。実機での一連の確認は未完了**。

`z2-action` は、名前付きの操作手順をテキストで保存し、CLI・シェルマクロ・パネル・タイル・`z2-when` から共通実行します。`z2-macro actions` も同じ入口です。パネルの有効化は不要ですが、実行には `z2-key permission` から「z2term Android操作」を有効にする必要があります。

## 保存と編集

以下を任意のUTF-8ファイルへ書き、`z2-action save demo /root/demo.actions` で保存します。`org.example.app` と座標は対象アプリに合わせて変更してください。`z2-app list` で起動可能なパッケージを確認できます。

```text
version=1
timeout=30
screen=current
launch org.example.app
wait 800
tap percent 50 40
wait 300
long-press px 100 300 700
swipe percent 50 75 50 25 450
scroll -600 2000 50 50
command z2-toast "完了"
```

`save NAME -` は標準入力を読みます。保存時に全手順を検査し、成功した場合だけ同名定義を置き換えます。不正な入力は既存の定義を変更しません。`screen=current` は保存時の実画面サイズ・向きへ展開されます。

保存先は共有ホームの `/root/.z2term/actions/NAME.actions` です。`show NAME` で定義を取得して編集し、もう一度 `save` してください。直接ファイルを編集した場合も実行前に再検査します。実行中の定義は開始時の内容で固定され、編集・削除は次回から反映されます。

## GUIで作成・編集する（0.8.574）

コマンド一覧 → 自動化 → 操作自動化を開くと、タブ内に一覧と編集画面が表示されます（0.8.586）。パネルの有効化は不要です。

1. 「新規作成」を押し、英数字・アンダースコア・ハイフンで名前を付けます。
2. 前面画面を操作する場合は、そのまま必要な操作を追加します。アプリを固定する場合は「手順を追加」から「アプリを起動」を選び、アプリ一覧から対象を指定します。画面の準備を待つ「待機」も追加してください。
3. タップ・長押し・スワイプ・時間指定スクロールなどを追加します。各行を押して数値やコマンドを編集し、⋮ メニューで順番を変更できます。対象指定だけの行も並びに含まれ、移動すると後続の操作対象が変わります。対象指定の行は実行数には含みません。
4. 「テキスト編集」で定義全体を直接編集できます。コメント・空行・未編集のシェルコマンドは保持します。フォームで扱えない行はテキストで修正します。256ソース行を超える操作列はテキスト編集で開きます。
5. 「保存」でCLIと同じ検査を通して保存します。名前を変えると別名保存になり、元の定義は残ります。既存名への意図しない上書きや、編集中にCLI側で変更・削除された定義の保存を拒否します。競合時は開き直すか別名で保存してください。

一覧の各行の右端で、▶ で実行、「複製」で複製、✎ で編集、✕ で削除します（0.8.603）。実行状態・手順番号・停止ボタンと、直近32件までの開始／分岐判定／終了記録を確認できます。対象アプリを指定しないマクロは、GUIの実行時にz2termをバックグラウンドへ移し、前面画面への切り替えを待ってから始めます。未保存の編集を閉じる・戻る・別タブへ切り替える場合は破棄を確認します。編集中のスワイプ閉じは抑止し、閉じるボタンから確認を通します。画面回転時には名前・定義・編集中の手順を保持します。

### フリーハンドで一括記録（0.8.605）

「手順を追加」→「フリーハンドで一括記録」から、次の2方式を選べます。

- **記録専用**: 透明な記録画面でタッチを受け取り、背後のアプリには送りません。
- **実操作を記録（root）**: `su` と Android の `getevent` でタッチ入力を読みます。入力機器を占有せず、背後のアプリを通常操作できます。rootの許可が必要です。直接入力・Type-B方式のタッチ画面を1台検出できる端末が対象で、複数のタッチ画面や機器へのアクセス拒否では開始しません。座標は機器の範囲と画面回転から変換するため、端末固有の座標補正がある場合は実機確認が必要です。

タップ・連続タップ・長押し・スワイプ・ピンチ・2本指操作を種類の選択なしで行い、指を離して「記録停止・反映」を押します。最初のタッチ前と最後のタッチ後の空白だけを除き、操作間の待ち時間、指を止めていた時間、途中の軌跡と速度変化、指を置く・離す時刻を保存します。実操作モードでは記録用の操作欄へのタッチも除きます。

記録対象はタッチの座標と時刻です。物理キーや入力文字の意味は記録しません。再生には従来どおり対象ウィンドウ内・キーボード外という制限があるため、システム操作は必要に応じてAndroidキー手順を手動追加してください。

結果は「フリーハンドの記録（1回再生）」という1つのグループになります。内部は `repeat 1`、`target current`、時刻付きの `touch` と操作間の `wait` で保存し、グループの前後に必要な待機を手動追加できます。取得した画面情報を反映し、必要ならマクロの制限時間を記録の長さに合わせて延ばします。マクロ全体は別途「保存」で確定します。

記録は2分以内、1回のタッチ操作は30秒以内、1操作で扱う指は2本までです。2本を離す前に別の指を追加し直す操作は記録できません。最大32操作で、既存の64命令・64 KiB制限も適用します。取消・消灯・ロック・画面変更・切断では取得を中止します。

再生は記録した時刻を使い、終点へ余分な待機を加えずに指を離します。Androidの入力間隔・処理遅延・対象アプリの慣性により実際の動作には差が出ます。2本目の指を途中から置く場合、最初の指が動き始めてから2本目を置くまでの区間はAndroid APIの制約で経路内を等速で再生します。両指の開始・終了時刻と、それ以降の速度変化は保持します。停止時は後続の移動を止め、送出済みの区間のあとで指を離します。通常の先行送出は約120ミリ秒までですが、2本目を途中から置く最初の区間は例外です。

### 手動のジェスチャーと配置（0.8.605）

手順の種類に「ダブルタップ」「ピンチイン」「ピンチアウト」「2本指スワイプ」を追加しました。2本指スワイプは同時に動く2本の指を表します。ピンチは中心と横方向の開始・終了間隔、2本指スワイプは1本目の始点・終点と2本目のX/Yオフセットを入力します。座標取得では両方の軌跡と所要時間を取り込み、記録した軌跡の手順に切り替わります。

直線スワイプ、ピンチ、2本指スワイプは「一定速度」「加速して払う」「減速」を選べます。「加速して払う」は終点まで速度を上げ、そのまま指を離します。通常の直線スワイプの座標取得でも、始点・終点に加えて実際の所要時間を反映します（1〜3000ミリ秒）。

保存済みの操作マクロの一覧で「配置」を押すと、クイック設定タイルの枠、または既存のエッジパネルを選べます。使用中のタイル枠への上書きは確認し、パネルには新しい実行項目を追加します。タイルが見えない場合はクイック設定の編集から追加してください。パネルのアプリ実行項目の編集でも、実行欄から操作マクロを選べます。

配置先には `z2-action start NAME` を保存します。この単独コマンドをタイルまたは通常のパネル実行項目（出力なし）から呼ぶと、通知欄・パネルを閉じ、前面アプリが約500ミリ秒安定してから再生します。ここでは前面のz2term自身も対象にできます。5秒以内に前面画面を確認できなければ操作せず終了します。コマンドの連結や出力あり・状態付きの項目は従来のシェル実行です。

### アプリを指定せず、前面画面で実行する

タップ・長押し・スワイプ・スクロール・要素操作は、対象アプリを指定せずに保存できます。例えば次の定義は、実行時の前面画面でスワイプします。

```text
version=1
screen=current
swipe percent 50 75 50 25 450
```

前面画面を使う手順があるマクロをGUIの「実行」から開始すると、z2termをバックグラウンドへ移します。別のアプリの前面表示が約500ミリ秒安定してから手順を開始し、5秒以内に確認できなければ操作を送らず終了します。この開始待ちは停止通知から取り消せます。

各手順の開始時に前面アプリを決め、1つのジェスチャー・スクロール・要素待機の間はその対象を保ちます。操作中に対象が変われば停止します。手順間の画面遷移には必要に応じて「待機」を追加してください。画面寸法・向き・対象窓・キーボード・消灯・ロックの検査も適用します。

特定のアプリに固定する場合は従来どおり `target PACKAGE` または `launch PACKAGE` を使います。途中から前面画面へ戻すには `target current` を追加します。手順編集の「対象アプリを指定」にある「実行時の前面画面」ボタンでも設定できます。

CLI・パネル・タイルからの開始でも対象未指定は前面画面を使います。これらの入口ではz2termを自動で背景へ移さないため、CLIでは必要な待機を先頭に置いてから対象画面へ切り替えてください。

### 画面の座標だけを取得する（0.8.579）

タップ・長押し・スワイプの編集欄で「座標を取得」を押すと、編集中のツール画面をバックグラウンドへ移し、画面上の座標を選ぶモードに入ります。アプリ起動や対象指定の手順は不要で、他のアプリを自動起動しません。ユーザー補助の「z2term Android操作」が必要です。

- 点を押すか、スワイプの始点から終点まで指を動かします。このタッチは背後の画面へ送りません。直線スワイプは始点・終点と実際の所要時間を取得します。途中の速度変化まで残す場合は一括記録を使います。
- 目的の画面へ移動したいときは「画面操作」で通常操作へ戻し、浮かぶ「座標を取得」で選択を再開します。
- 選択を描き直して確認し、「反映」で数値入力へ戻します。操作欄は上下に移動でき、「取消」で元の操作自動化タブ内の編集へ戻れます。取得時にはアプリの種類や対象窓との一致を検査しません。
- 座標は選択中の単位（px／percent）へ戻し、画面寸法と向きも保存対象にします。既存の画面情報と異なる場合は、他の座標を確認してから画面設定を明示的に更新してください。
- 消灯・ロック・画面寸法や向きの変更・ユーザー補助切断・2分経過で取り消します。取得とマクロ実行は同時に行えず、取得中はエッジパネルを一時非表示にします。

取得した値だけを編集中の手順へ戻し、アプリ起動・待機・対象指定の手順は追加しません。通常の座標取得は1回の操作を取得し、画像やUI要素は読み取りません。複数の操作には上記の一括記録を使います。操作対象を指定せずに保存でき、その場合は各手順の実行時の前面画面を対象にします。実行時には対象窓内・キーボードより上の領域を検査します。数値を直接入力するCLIとも同じ定義を使います。

設定画面の開閉状態とスクロール位置はバックグラウンド復帰・アプリロック解除後に復元します。操作マクロの下書き・編集中の手順・スクロール位置も保持します。ロック中は設定や編集内容を表示しません。ビルド未検証・実機未確認。

## 反復・条件分岐・マクロの再利用（0.8.573）

これらの命令には `version=2` が必要です。従来の `version=1` もそのまま実行できます。

例えば、次を `pause` という名前で保存します。

```text
version=1
timeout=5
wait 800
```

続いて次を別名で保存すると、条件が成立した回だけ `pause` を呼びます。

```text
version=2
timeout=30
repeat 3
  if charging,level>20
    call pause
  else
    wait 300
  end
end
```

- `repeat N ... end`: 1〜10000回。各回の処理が終わってから次へ進みます。`repeat forever` は停止・失敗・制限時間・実行数の上限に達するまで続けます。
- `if 条件 ... else ... end`: 条件をその場で評価し、成立側だけ実行します。`else` は省略できます。反復内では毎回評価します。空のブロックや明示した空の `else` は保存できません。
- `call 名前`: 保存済みのマクロを呼び、完了してから戻ります。子マクロも自分の `timeout` を持ち、親の残り時間と両方が適用されます。どの階層の失敗・停止・タイムアウトでも実行全体が終了します。

保存時は構文と条件式を検査します。呼び出し先は後で作成でき、存在確認・循環検出は開始時に行います。選ばれない分岐も含めて呼び出し先と画面情報を検査し、全定義を固定してから最初の動作を送ります。実行中の保存・削除は次回から反映されます。

`target` / `launch` で指定した対象はブロックの内側へ引き継ぎ、`else` と `end` では外側の対象へ戻ります。子マクロは親の対象指定を引き継がず、未指定なら各手順の実行時の前面画面を使います。これは定義の対象指定であり、前面アプリを自動で元に戻す動作ではありません。必要なら復帰後に `launch` と `wait` を書きます。

### 条件式

カンマ区切りはAND、各項目の先頭の `!` は否定です。括弧・OR・引用符によるエスケープは扱いません。項目は最大16個です。

| 種類 | キー | 書式 |
|---|---|---|
| 真偽値 | `screen locked idle charging wifi airplane headset bt_audio` | `charging`、`!wifi`、`screen=true`。true/on/yes/1 と false/off/no/0 を使用可能 |
| 数値 | `level temp volume volume_max` | `level>20`、`temp<40`、`volume=0`。比較は = / < / > |
| 文字列 | `ssid ringer plug foreground` | `ringer=silent`、`foreground=org.example.app`。比較は = |

状態は `z2-state` と共通のスナップショットを使います。`foreground` は前面ウィンドウのパッケージ名で、UI要素の内容は読みません。文字列は大文字小文字を区別しませんが、パッケージ名だけは区別します。評価する値が欠落・空欄、または数値の取得失敗値 `-1` なら実行を失敗として止め、`else` へは進めません。ANDは左から評価し、不成立が確定した後の項目は評価しません。

### GUI・制限・実行位置

ブロックを階層表示して編集できます。各グループ末尾の「手順を追加」から単一手順・繰り返し・条件分岐を選び、見出しで回数や条件式、子の行で手順を編集します。⋮ メニューでは同じ階層内の上下移動、別グループ末尾への移動、複製、削除ができます。対応する else / end と本文内の先行コメントをまとめて扱い、自分自身の内部への移動を拒否します。if のメニューで不成立側を追加・削除できます。空にした内部には手順を追加してから保存してください。呼び出し先もフォームの一覧から選べます。制御命令・要素操作の追加時に version=2 へ切り替えます。テキストと階層編集を切り替えられ、構造不正や256ソース行超過の場合はテキストで修正します。

定義ごとに64命令・64KiB、ブロックは8階層までです。命令数には `repeat` / `if` / `call` と両分岐を含み、`target` / `else` / `end` は含みません。呼び出しは最上位を含め8階層、ブロックと呼び出しの合計は16階層、参照する定義は64件までです。展開後の実行は全体で10000命令まで。反復を事前に展開せず、制御命令や反復の切り替わりで待ち時間を挟み、停止要求を受け付けます。

反復・分岐・呼び出しがある場合、`status` / `history` の `total` はJSONの `null`、`step` は制御命令を含む累計実行数です。`action_macro` は現在の定義名、`path` はその定義内の1始まりの階層位置（分岐の成立側は yes、不成立側は no を挟む）、`iteration` は最も内側の反復の回数、`call_depth` は最上位を1とする呼び出し階層です。条件の判定は `state=branch`、`detail=true/false` で記録します。GUIにも実行位置・反復回数と条件の判定結果を表示します。

手順と分岐の履歴は最大250ミリ秒分をまとめて保存し、開始・終了時は即座に保存します。プロセス強制終了では未保存分が残らない場合があります。

## UI要素の指定と出現待ち（0.8.574）

`version=2` で、対象アプリがユーザー補助へ公開する表示文字・説明・要素IDを指定できます。

```text
version=2
timeout=30
launch org.example.app
wait-ui 5000 text=準備完了
click id=org.example.app:id/next
wait-ui 5000 desc=その他の操作
long-click desc=その他の操作
```

| 命令 | 動作 |
|---|---|
| `click 対象` | 要素を1回押す |
| `long-click 対象` | 要素を1回長押し |
| `wait-ui MS 対象` | 要素の表示を1〜30000ミリ秒待つ |
| `z2-action inspect PACKAGE` | 前面の対象アプリの要素をJSONで取得。マクロ内の命令ではなくCLIコマンド |

対象は `text=次へ`、`desc=その他の操作`、`id=org.example.app:id/next` のいずれか1つです。文字・説明は前後の空白を除いて完全一致し、大文字小文字を区別します。値は1〜256文字。途中の空白や `=` はそのまま書き、引用符も文字として扱います。シェル展開・正規表現・部分一致は使いません。

先行する `target` / `launch` の対象を使い、未指定または `target current` なら各手順の開始時に前面アプリを解決します。ブロックと子マクロの対象指定も座標操作と共通です。要素だけの新規マクロに `screen` は不要です。GUIは座標操作の追加時に画面情報を記録し、画面情報の編集欄を空欄にすると既存の指定を外せます。保存済み画面情報がある場合の一致検査と、実行中の消灯・ロック・回転による停止は維持します。

`wait-ui` は対象アプリが前面になるまでの時間も含めて待ちます。最初に対象を確認した後、別アプリへ切り替わると停止します。未発見や画面切り替えで古くなった要素情報は、検索終了から250ミリ秒後に再検索します。手順と親・子マクロのうち最も早い期限が適用されます。表示待ちなので、無効なボタンでも表示されていれば待機は終了し、押せるかどうかは操作時に検査します。

複数一致・対象違い・探索上限超過では操作しません。要素自体に要求した動作がなければ、同じ対象窓内で最も近い操作可能な親を8階層まで探します。操作直前に再確認し、Androidの拒否では失敗として終了します。押す操作は再送せず、座標への自動置き換えも行いません。操作要求の成功と画面遷移完了は別なので、次の画面に必要な `wait-ui` を続けて指定します。

### 対象アプリから要素を選ぶ

フォームの「対象アプリから選ぶ」を押すと、対象未指定または `target current` ではz2termをバックグラウンドへ移し、アプリを指定済みならそのアプリを開きます。目的の画面へ進んで「要素を取得」を押します。一覧の文字・説明・IDを選ぶと下書きへ戻ります。この選択では対象要素を押しません。再取得、操作欄の上下移動、取消ができます。座標取得と同じく2分経過・画面変更・消灯・ロック・ユーザー補助切断で終了し、選択とマクロ実行は同時に行えません。

要素命令・選択・明示的な一覧取得の間だけ、前面の対象窓を読みます。編集可能な入力欄・パスワード欄とその子要素、別パッケージの埋め込み内容は対象外です。取得一覧を履歴へ保存せず、選んだ指定だけをマクロのテキストとして保存します。ユーザー補助の説明も更新しています。

探索は最大1024ノード・1.5秒の処理時間枠、一覧は最大256件、取得は同時1件です。問い合わせはGUIや通常のCLI処理と分け、停止要求を受け付けます。既に応答待ちのAndroid APIは即時中断できない場合がありますが、中断された問い合わせから操作は送りません。要素を公開しない画面には座標操作を使います。

実装の参照: Android [AccessibilityNodeInfo](https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo)、[FLAG_REPORT_VIEW_IDS](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo#FLAG_REPORT_VIEW_IDS)。

## コマンド

| コマンド | 動作 |
|---|---|
| `z2-action list` | 保存名を一覧表示 |
| `z2-action show NAME` | 保存済み定義を表示 |
| `z2-action save NAME FILE` | 検査して保存。FILEが `-` なら標準入力 |
| `z2-action delete NAME` | 定義を削除 |
| `z2-action run NAME` | 完了まで待つ。成功は終了コード0、失敗・停止・タイムアウトは非0 |
| `z2-action start NAME` | 実行を要求し、実行IDを返す |
| `z2-action wait RUN_ID` | 指定した実行の完了待ち |
| `z2-action status [RUN_ID]` | JSONで状態・手順番号・結果を取得 |
| `z2-action stop [RUN_ID]` | 残りの手順を停止。ID省略時は現在の実行 |
| `z2-action inspect PACKAGE` | 前面の対象アプリの表示文字・説明・IDをJSONで取得 |
| `z2-action screen` | `screen=幅x高さ@向き` を取得。向きは0/1/2/3 |
| `z2-action history` | 最近256件までの開始・手順開始・分岐判定・終了記録をJSONで取得 |

同時実行は1本です。別の実行要求で既存の実行を置き換えることはありません。終了結果はプロセス内で直近32実行を保持し、履歴は `/root/.z2term/actions/.history.jsonl` に残します。プロセス終了後は `history` で確認してください。処理の再開・再試行は自動では行いません。

`run` をCtrl+C等で中断すると、その実行IDだけに停止を要求します。`wait` の中断だけでは実行を止めません。通知の「マクロを停止」からも止められます。通常のタッチはAndroidに送信済みの操作が終了まで残るため、停止要求後も最大3秒続く場合があります。時刻付き軌跡は送信済み区間の終了後に指を離します。2本目の指が後から加わる最初の区間が長い場合は、上記の例外が適用されます。後続の手順は送信しません。

## 定義の書式

ヘッダーの後に1行1手順を書きます。空行と `#` で始まる行は無視します。

| 書式 | 意味 |
|---|---|
| `version=1` / `version=2` | 必須の書式番号。反復・分岐・呼び出しは2 |
| `timeout=30` | 全体の制限時間。秒、1〜300、既定30 |
| `screen=current` | 保存時の画面情報。座標操作・スクロールでは必須 |
| `screen=1080x2400@0` | 画面情報を直接指定 |
| `target PACKAGE` | 後続の座標・スクロール・要素操作の対象アプリ。アプリは起動しない |
| `target current` | 後続の各手順の実行時に前面画面を対象とする。対象未指定時の既定動作 |
| `launch PACKAGE` | アプリを起動要求し、後続の対象も切り替える |
| `wait MS` | 0〜30000ミリ秒待つ |
| `key NAME` | back/home/recents/shade/quicksettings/screenshot/split |
| `tap UNIT X Y` | 80ミリ秒のタップ |
| `long-press UNIT X Y MS` | 500〜3000ミリ秒の長押し |
| `swipe UNIT X1 Y1 X2 Y2 MS [EASING]` | 1〜3000ミリ秒の直線スワイプ。既定は一定速度 |
| `double-tap UNIT X Y GAP` | 80ミリ秒のタップを2回。離してから次に触れる間隔は40〜300ミリ秒 |
| `pinch-in` / `pinch-out UNIT CX CY START END MS [EASING]` | 中心と開始・終了時の指の横間隔 |
| `swipe-two UNIT X1 Y1 X2 Y2 DX DY MS [EASING]` | 2本指の同時スワイプ。2本目はDX・DY分ずらす |
| `touch UNIT X,Y,MS ...` | 時刻付きの記録。`\|`で2本目を指定でき、指ごとに押下・離指時刻を保持。version=2 |
| `swipe-path` / `swipe-two-path UNIT X,Y,MS ...` | 時刻付きの軌跡。2本の軌跡は同じ標本時刻。version=2 |
| `scroll SPEED MS X Y` | 時間指定の自動スクロール。符号付き50〜40000dp/秒、1〜30000ミリ秒。X/Yは対象窓内の10〜90% |
| `command SHELL_TEXT` | 既存Linux実行経路でシェルコマンドを実行し、終了を待つ |

座標のUNITは `px` または `percent` を明示します。画面左上が原点で、百分率は画面全体の0〜100です。`scroll` の位置だけは対象窓内の百分率です。負のスクロール速度で内容を先へ、正で戻る方向へ動かします。実際の移動量は対象アプリに依存します。

EASINGは `linear`（一定）、`accelerate`（加速して払う）、`decelerate`（減速）です。手動のピンチと2本指スワイプは1〜3000ミリ秒です。記録した軌跡は各指2〜2048点、時刻は増加順で最大30000ミリ秒です。1本目の開始は0で、`touch` の2本目は1本目と接触期間が重なる範囲で遅れて開始できます。

タップとスワイプは、対象アプリの可視ウィンドウ内で、キーボードを除いた領域に限定します。画面寸法・向きが保存値と違う場合、対象アプリが前面にない場合、消灯・ロック・ユーザー補助切断では停止します。ユーザー補助を有効にした直後など対象アプリを識別できない場合は、そのアプリへ切り替えてから実行してください。

操作が完了してから次の手順へ進みます。コマンドは終了コード、タッチはAndroidの完了通知を確認します。取消・拒否・完了通知の欠落では後続を実行しません。時間指定スクロールは最後の送信済みスワイプが終了するまで待ちます。`launch` は起動要求の受付までなので、画面が準備できるまでの `wait` を明示してください。

マクロは最大64ソース命令・64KiB、保存数は64件、名前は英数字・`_`・`-` の1〜64文字です。実行中はパネルと取っ手を一時非表示にします。未保存のパネル編集がある場合は実行を断り、保存または取消を先に行います。

## 既存の自動化から呼ぶ

- シェルマクロでは `z2-action run demo` を1行として呼べます。実行を開始するトリガーと条件は引き続き `z2-when` やシェルで作成します。
- 例: `z2-when charge:start if=screen run 'z2-action run demo'`。対象の画面状態を確認できない場合、マクロは失敗として終了します。
- 取っ手のコマンドやパネル項目には `z2-action start demo` を設定できます。項目設定のマクロ一覧からも選択できます。
- タイルには `z2-tile set 1 'z2-action start demo' --off 'z2-action stop' -l 操作` のように開始・停止を割り当てられます。この入切表示はタイル側の記憶であり、マクロの完了状態との自動同期は行いません。`status` と実行通知で確認できます。

タッチ操作の一括記録は0.8.605で実装しています。動画の録画と画像認識は別途の調査対象です。[ロードマップ](AUTOMATION-ROADMAP.md)を参照してください。

Android側の完了通知と能力設定は[AccessibilityService公式仕様](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#dispatchGesture(android.accessibilityservice.GestureDescription,%20android.accessibilityservice.AccessibilityService.GestureResultCallback,%20android.os.Handler))に基づきます。
