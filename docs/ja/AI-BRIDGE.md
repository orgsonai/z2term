# AI から Android アプリを操作する `z2-ui`

状態: **第 1 段を 1.0.30、第 2 段を 1.0.31、第 3 段を 1.0.32 で実装**（§10）。残る調査事項は仮想画面（§8）だけです。

## 1. 目的

z2term を「AI と Android アプリの間に立つ API」にします。AI はターミナルのコマンドだけで、専用 API を持たないアプリの画面を読み、押し、文字を入れ、結果を確かめられるようにします。

- AI は「見る → 決める → 1 手打つ → 結果を見る」を繰り返します。そのため、1 回の呼び出しは短く、出力は機械が読める JSON に揃えます。
- アプリ側の協力は要りません。Android のユーザー補助（AccessibilityService）が公開する画面の情報だけを使います。
- AI の種類は問いません。z2term の中で動く AI、SSH 越しの PC の AI、のちに MCP（AI とツールをつなぐ共通の取り決め）に対応した AI から、同じコマンドを使えます。

## 2. 現状と不足

既存の `z2-action` は「人が手順を作り、保存して、何度も再生する」ための仕組みです。AI が使うには次の点が足りません（コードで確認済み）。

| 項目 | 現状（`z2-action`） | AI に必要なもの |
|---|---|---|
| 画面の読み取り | `inspect PACKAGE` は `id` / `text` / `desc` の 3 項目だけを返す。位置・種類・押せるか・階層は返さない | 位置・種類・押せるか・スクロールできるか・選択状態 |
| 前面アプリ | 読み取るには、前面のパッケージ名を先に知っている必要がある | 「いま前面にあるもの」を問い合わせる手段 |
| 入力欄 | 入力欄・パスワード欄は、その中身ごと読み取りから外している | 入力欄の場所と、パスワード以外の中身 |
| 操作 | 保存した定義の再生だけ。1 手だけ即座に打つ入口が無い | 1 手ずつの即時実行 |
| 文字入力 | 命令が無い | 入力欄への文字入れ |
| 画像 | `z2-shot` は指で囲む操作が前提 | 操作なしで 1 枚ファイルに保存 |
| 安全 | 人が書いた手順なので、ユーザー補助の許可だけで動く | AI 用の許可・確認・停止・記録 |

## 3. 全体像

```
AI（z2term 内 / SSH 越し / MCP）
   │  z2-ui look / tap / type …（標準出力に JSON）
   ▼
z2api ブリッジ（既存のファイル受け渡し方式）
   ▼
AI 操作の受付（新規）── 許可・確認・停止・記録をここで一括判定
   ▼
ユーザー補助サービス「z2term Android 操作」（既存）
   ▼
前面の Android アプリ
```

- 新しい権限は要りません。既存のユーザー補助サービスを使います。
- 画面の読み取りと操作は `AndroidUiLook` が行います。`AndroidUiElements`（z2-action）と同じく、前面の窓とパッケージを確かめ、別のアプリの埋め込み内容には入りません。違いは、入力欄を読むこと（パスワード欄は除く）と、位置・種類・できる操作を返すことです。撮影には `RegionShot` と同じ `takeScreenshot` を使い、撮影間隔の制限は画面端のバーの自動配色と時刻を共有して守ります。
- `z2-action` は変更しません。保存して再生する用途は今までどおり `z2-action` で、AI の 1 手ずつの操作は `z2-ui` で行います。両者は同時に動かしません（片方が動いている間、もう片方は「busy」で断ります）。

## 4. コマンド

すべての出力は 1 行の JSON です。成功したら終了コードは 0、失敗したら非 0 です。失敗のときも `{"ok":false,"error":"<コード>","message":"…"}` を出すので、AI は理由で次の手を分けられます。

### 4.1 見る

| コマンド | 返すもの | 段 |
|---|---|---|
| `z2-ui front` | 前面のパッケージ名・アプリ名・そのアプリの段階・画面寸法・向き・ロック中かどうか | |
| `z2-ui look` | 前面の画面の要素一覧（下の例）。`--all` で意味の無い入れ物も含めて全部 | |
| `z2-ui look --tree` | 同じ内容を親子関係つき（`tree` の中の `children`）で返す。番号は平らな一覧と同じなので `#N` はそのまま使える。出していない入れ物は飛ばし、一番近い祖先の子として並べる | |
| `z2-ui look --in N` | 直前の `look` の要素 N の中だけを読む。要素が多い画面でも、上限（512 要素）を一部に絞って読める | |
| `z2-ui shot [--scale 0.1..1] [--jpeg] [--stable [MS]]` | `--stable` は画面の動きが止まるまで（続けて撮った 2 枚がほぼ同じになるまで、最大 MS、既定 3000）待ってから撮る（1.0.36）。前面のアプリの窓の範囲だけを `/root/.z2term/ui/shot.png`（`--jpeg` なら書き出しが速く小さい `shot.jpg`）に保存し、`path`・画像の `size`・画面上の範囲 `box`・`scale` を返す。画像の (x, y) は画面の (box.x + x / scale, box.y + y / scale)。通知欄やほかのアプリが写らないよう、窓の外は切り落とす。撮るたびに同じファイルへ上書きし、2 分呼ばれなかったときと停止したときに消す（MCP は画像を返したらすぐ消す、1.0.37） | |
| `z2-ui status` | 許可の状態（ON/OFF・停止・一時停止・既定の段階・アプリごとの段階・まとめて許可の残り秒・常に断るアプリ） | |

起動できるアプリの一覧は `z2-app list` を使います（`z2-ui apps` は置きません）。`--all`・`--tree`・`--in N` は組み合わせられます。

`look` の出力例:

```json
{"ok":true,"screen":"s41","package":"org.example.app","app":"Example","size":[1080,2400],"rotation":0,
 "elements":[
  {"n":1,"role":"button","text":"次へ","id":"org.example.app:id/next","box":[820,2210,220,120],"can":["tap"]},
  {"n":2,"role":"input","hint":"検索","value":"","box":[60,180,960,110],"can":["tap","type","enter"]},
  {"n":3,"role":"list","box":[0,320,1080,1800],"can":["scroll"]},
  {"n":4,"role":"check","text":"通知を受け取る","checked":true,"box":[60,520,960,100],"can":["tap"]}
 ]}
```

- `screen` は画面の識別番号です。`look` のたびに新しく振ります。
- `n` は、その `look` の中だけで通じる要素番号です。
- `role` は `button` / `text` / `input` / `password` / `check` / `switch` / `list` / `image` / `other` のどれかです。Android の要素の種類（class 名）と、できる操作から決めます。
- `box` は `[x, y, 幅, 高さ]` を画面の px で表します。
- `can` は、その要素に Android が許している操作です。要素自体が押せなくても、8 階層以内の親が押せれば `tap` を出します（押すとその親へ送ります）。値の無い項目（`desc` など）は出しません。押せない状態の要素には `"enabled":false` が付きます。
- 意味の無い入れ物（文字も説明も操作も無い要素）は出しません。AI に渡す量を減らすためです。`--all` を付けると全部出します。
- 入力欄は場所・ヒント・中身を出します。**パスワード欄は種類と場所だけを出し、中身は出しません。**
- 上限は 1 画面 512 要素・3000 ノード・1.5 秒です。超えたら `error:"too_many"` / `"too_large"` を返します。そのときは `look --in <n>` で範囲を絞ります（ノードの上限と時間は絞っても同じです）。

### 4.2 操作する

要素は次のどれかで指定します。

| 書き方 | 意味 |
|---|---|
| `#2` | 直前の `look` の要素番号 |
| `text=次へ` / `desc=戻る` / `id=…` | 既存の `z2-action` と同じ完全一致の指定 |
| `@540,1200` | 座標（px）。要素が取れない画面の最後の手段 |

| コマンド | 動作 | 段 |
|---|---|---|
| `z2-ui tap <要素>` | 押す | |
| `z2-ui long <要素> [--hold MS]` | 長押しする。座標（`@X,Y`）なら `--hold` で指を置く長さを決められる（100〜10000 ミリ秒、既定 600、1.0.37） | |
| `z2-ui type <要素> "文字" [--append]` | 入力欄の中身を置き換える（`--append` なら末尾に足す）。最大 4096 文字 | |
| `z2-ui enter <要素>` | 入力欄で確定キー（検索・送信など）を押す。先に入力欄へフォーカスを移す。Android 11 から（10 では `unsupported`） | |
| `z2-ui key back\|home\|recents` | Android 全体の操作をする。`back` は前面のアプリの中で効くので操作として扱う（段階・承認の対象） | |
| `z2-ui open <パッケージ名\|URI>` | アプリや特定の画面を開く。パッケージ名は `look` 以上なら開ける。URI は相手のアプリに何かをさせうるので操作として扱う。z2term 自身へは常に戻れる | |
| `z2-ui wait <text=\|desc=\|id=> [MS]` | 要素が出るまで待つ（既定 5000、最大 30000）。`#N` と座標は使えない | |
| `z2-ui wait-change [MS]` | 直前の `look` から画面が変わるまで待つ | |
| `z2-ui scroll <要素> up\|down\|left\|right` | 1 画面分スクロールする。要素か 8 階層以内の祖先の、向きのあるスクロール（無ければ前へ・先へ）を使う。座標は使えない（`swipe` を使う） | |
| `z2-ui swipe X1 Y1 X2 Y2 [MS]` | 座標でスワイプする（既定 300、50〜3000 ミリ秒）。始点・終点とも前面のアプリの窓の中だけ | |
| `z2-ui drag X1,Y1 X2,Y2 … [--step MS]` | 指を離さずに、すべての点を順に通る 1 本の操作（1.0.34）。2〜256 点、1 区間あたり 20〜1000 ミリ秒（既定 100）、全体で 30 秒まで。速さは道のり全体で一定。なぞる途中で指を離すと終わる画面（パズル・お絵かき）のためのもの | |

**操作のあとの画面も返す（1.0.36）**: 操作の命令（`tap` / `long` / `type` / `enter` / `key` / `open` / `scroll` / `swipe` / `drag` / `noti press`）に `--shot` を付けると、操作のあと画面の動きが止まるのを待ってから（最大 3 秒、`--settle MS` で 10 秒まで）前面のアプリの窓を撮り、結果の `shot` に入れて返します（縮小 0.5 の JPEG）。MCP では `"shot": true` で、画像も一緒に返ります。AI は押すたびに撮り直す必要が無くなり、1 手で考える回数が 2 回から 1 回になります。

**指を置いたまま撮る（1.0.37）**: `long @X,Y` / `swipe` / `drag` に `--peek MS` を付けると、指を置いてから MS 後、**指を離す前に**前面のアプリの窓を撮り、結果の `peek` に入れて返します（縮小 0.5 の JPEG、MCP では `peek_ms`）。長押しやなぞる途中にだけ出る表示（操作の残り時間など）は、指を離してから撮ると消えているためです。`held` が true なら、撮り終えた時点でまだ指が置かれていました。MS は操作の長さより短くし、撮影が Android の間隔の制限で最大 約 0.3 秒待つことがあるので、後ろに 300 ミリ秒ほど余裕を残します。`--shot` と一緒に使えます。

座標の操作（`tap @X,Y` / `long @X,Y` / `swipe` / `drag`）は、操作が終わるとすぐ返り、`changed` を返しません（1.0.34）。座標で操作する画面（ゲームなど）は要素を持たない 1 枚の絵で変化を検出できず、見張ると毎回 1 秒まるまる待つことになるためです。結果は `shot` で確かめます。

`scroll` と `swipe` も操作として扱います（段階・承認の対象）。スクロールしただけで既読になるアプリなどがあり、「読むだけ」の約束（何も変えない）を守れないためです。

通知欄を開く `key shade` は置きません。通知欄（システム UI）は常に操作させない画面なので、開いても AI には何もできないためです。

**番号の取り違えを防ぐ約束:**

- `#n` を使う操作では、直前の `look` の要素と、いま画面にある要素を照らし合わせます。種類・文字・ID・位置の一つでも違えば、操作せずに `error:"stale"` を返します。AI はもう一度 `look` すれば続けられます。
- 押す前に要素が変わっていたら、押しません。操作の再送や、座標への自動の置き換えもしません。ここは `z2-action` と同じです。
- 操作が成功すると、`{"ok":true,"changed":true|false}` を返します。`changed` は 1 秒以内に画面が変わったかどうかです。画面遷移が終わったことまでは保証しないので、AI は必要なら `wait` や `look` を続けます。

### 4.2.1 速く動かす: 色を文字で読む・まとめて送る（1.0.38）

AI がいちばん時間を使うのは、呼び出しのあいだに「画像を読んで考える」ところです（実機の記録では 1 手 5〜10 秒、z2-ui 自体は 1 回 約 0.2 秒）。そこで、考える回数と読む量を減らす 2 つの命令を足しました。どのアプリでも使えます。

| コマンド | 内容 |
|---|---|
| `z2-ui colors X,Y [X,Y …] [--radius R] [--stable [MS]] [--hex]` | 画面の点の色を**名前の文字**で返す（画像は保存しない）。名前は black・gray・white・red・orange・brown・yellow・green・cyan・blue・purple・pink。各点は半径 R（既定 4、0〜20）px 四方の中央値なので、光沢や縁の 1 点に引っぱられない。`colors` に点ごとの `{x, y, name, hex}` |
| `z2-ui colors --grid X0,Y0 DX,DY 列x行 …` | 格子状に並んだ点をまとめて読む。X0,Y0 は左上のマスの中心、DX,DY はマスの間隔（負でもよい）。`grid` は 1 行を 1 つの文字列にしたもの（例 `["red blue green blue pink yellow", …]`）。`--hex` で `#rrggbb` も付く。最大 400 点 |
| `z2-ui seq 手 -- 手 -- …` | 決まっている手順を**まとめて 1 回で**送る。手は `z2-ui` を除いた普通の命令（例 `z2-ui seq tap '#3' -- wait 'text=完了' -- tap 'text=OK' --shot`）。`sleep MS`（1〜10000）で待てる。最大 32 手 |

- `colors` の許可は `shot` と同じ（読むだけでよい）。`--stable` は画面の動きが止まるまで待ってから読む。盤面のマス・状態を色で示すランプ・要素を持たないスイッチなど、「決まった場所の色」で分かる状態に使う。並びを知るために 1 度だけ撮り、場所を覚え書きに書いておけば、あとは画像を読まずに済む。
- `seq` に入れられるのは front・look・shot・colors・tap・long・type・enter・key・open・scroll・swipe・drag・wait・wait-change・noti・sleep。失敗した手で止まり、`failed_step`（何手目か）とそれまでの各手の結果（`steps`）を返す。
- `seq` の各手は単独で呼んだときと同じ判定・記録を通る（「毎回確認」の承認・一時停止・指示・停止も 1 手ごとに効き、`mark` → `save` にも残る）。始めてから 60 秒を過ぎたら次の手を始めない（`timeout`）。
- 画像を作る手（`shot`・`--shot`・`--peek`）は最後の 1 手だけ。同じファイルへ上書きするため、途中の画像は返す前に消えてしまう。
- **範囲を絞る・変わっていなければ返さない（1.0.39）**: `shot` と操作の `--shot` に `--box X,Y,W,H`（画面のピクセル）を付けると、その範囲だけを撮ります（`--peek` にも効く）。画像が小さいほど AI は速く読めます。`--if-changed` を付けると、前に保存した画像（同じファイル名・範囲・縮小）と同じ画面なら、書かずに `{"ok":true,"unchanged":true}` だけを返します（MCP では画像を付けない）。判定は厳しめで、数字 1 つの書き換えも「変わった」とみるので、`unchanged` なら見えるものは何も変わっていません。MCP では `box`・`if_changed`。
- **繰り返しは手元のスクリプトに任せる（1.0.45、AI 用ガイド）**: 「状態を読む → 次の操作を計算する → 操作する → 結果を待つ」が繰り返すなら、AI が 1 回ずつ考える代わりに、z2-ui を呼ぶ小さなスクリプトを端末で書いて回すよう、AI 用ガイドに書きました。AI の 1 往復（5〜10 秒）が無くなります。スクリプトは、知らない状態（`ok` が false・思っていない色・回数や時間の上限）でそこで止まって AI に戻し、一時停止・指示・停止は AI と同じく 1 回ごとに効きます（受けたらすぐ止まる）。利用者が繰り返しを頼んだときだけ書き、走らせる前に何をするかを伝え、読める場所に置きます。自動操作を利用規約で禁じているアプリやサービスがあることも、当てはまりそうなら利用者に伝えます。専用の常駐パイプは作っていません（縮むのは 1 回 約 0.2 秒だけで、撮影の間隔は変わらないため）。
- **止まったかの判定を選ぶ（1.0.44）**: AI 操作の設定画面の「小さな動きも「動いている」とみる」（既定 ON）で、1.0.42 の厳しめの判定（区画ごとにも見る）を使うかを選べます。OFF にすると 1.0.41 までの、画面全体の平均だけで見る判定になります。一部がずっと動いている画面（待機中のアニメーションなど）で毎回最大まで待たされるときに OFF にします。AI は呼び出しごとに `--settle-check strict|loose`（`shot`・操作の `--shot`・`colors`、MCP では `settle_check`）で選べ、こちらが設定より優先します。
- **色が条件を満たすまで待つ（1.0.43）**: `colors … --until 条件 [--within MS]`。画像を作らずにアプリの中で撮り直し（Android の撮影の間隔の下限で、約 1/3 秒ごと）、条件を満たした時点の色を返します。条件は `brighter N` / `darker N`（点の明るさの平均、0〜255）、`changed`（どれかの点の色の名前が最初と変わった）、色の名前（すべての点がその色）。`--within` は最大待ち（1〜30000 ミリ秒、既定 10000）。`--stable` を付けると、満たしたあと動きが止まるのも待ちます。時間切れは `not_met` で、最後に読んだ色も返します。AI が「撮る → 画像を読む → まだ待つと決める」を繰り返す往復（1 回 5〜10 秒）を、約 1/3 秒ごとの確かめに置き換えるものです。閾値はアプリごとに違うので、AI が状態ごとに一度 `--hex` で測って覚え書きに残します。例: `z2-ui seq drag … -- colors --grid … --until brighter 120 --within 20000 --stable`。MCP では `until`（`"brighter 120"` のような 1 つの文字列）と `within_ms`。
- **待ち時間を減らす（1.0.42）**:
  - 「動きが止まったか」の判定を厳しくしました。画面全体の平均の差に加えて、小さな区画ごとの差も見ます（一部の駒が消える・小さなダイアログ・数字の表示のように、画面の 1 割に満たない動きでも「まだ動いている」とみます）。`--box` を付けたときは、その範囲の中の動きだけを見ます。`colors --stable` は点のまわりだけを見ます。
  - `--expect-change`（`shot` と操作の `--shot`、MCP では `expect_change`）: 止まるのを待つ前に、前回返した画像から変わるまで最大 1.5 秒待ちます。反応が遅い画面で、操作前の静かな画面を「止まった」と返さないためのものです。結果の `changed` で変わったかが分かります。
  - `--grid X0,Y0 DX,DY 列x行`（`shot` と操作の `--shot`、MCP では `grid`）: 同じ 1 枚から色も読み、画像と一緒に `grid` を返します。`colors` を別に呼ぶ必要がありません。
  - `seq` の `--peek` は、どの手でも 1 回まで使えます（画像が別ファイルなので上書きし合いません）。`shot`・`--shot` は今までどおり最後の手だけです。
  - `drag --hold MS`（0〜2000、既定 0、MCP では `hold_ms`）: 動き出す前に始点で指を止めます。触れてすぐ動くと「掴んだ」と認めない画面で、1 区間の時間（`--step`）を短くできます。手順として保存するときは、始点を重ねて同じだけ止めます。
- MCP では `colors`（`points` か `grid`: `{origin, step, cols, rows}`）と `seq`（`steps`: `[["tap", "@540,700"], ["sleep", "500"]]`）。

### 4.3 パスワードと保護された画面

- パスワード欄へは `type` しません（`error:"password"`）。認証の入力は人が行います。
- 撮影を禁じている画面（銀行アプリなど。Android の `FLAG_SECURE`）では、Android が黒く塗った画像を返します。`shot` は Android 11 以降で使えます（それより前は `error:"unsupported"`）。要素の読み取りは、アプリがユーザー補助へ公開している範囲だけです。

## 5. 安全装置

AI が任意のアプリを押せるようになるので、`z2-ui` の可否の判定はすべて受付（§3）の 1 か所で行います。`z2-ui` のどの書き方でも、この判定を飛ばすことはできません。

⚠ **これは「AI がうっかり広げない・押し間違えない」ための仕組みで、AI がわざと回り道をすることは防げません。** AI はターミナルのシェルを持っているので、`z2-action`（座標で押すマクロ）や `cmd` など、`z2-ui` 以外の手段にも手が届きます。AI 側にも使ってよいコマンドを決める設定があるなら、そこで `z2-ui` だけを許すと確実になります。z2term の側では、次のことだけを保証します。

- `z2-ui` の操作を送っている間（承認待ちを含む）は、`z2-action` を始めさせない。承認のバナーを座標で押させないためです。
- 通知のボタン（「許可」「再開」など）は、プロセス内の印を持つ通知からの操作しか受け付けない。AI が同じ uid で放送を打っても押したことにはなりません。

### 5.1 既定は OFF

コマンド一覧 › 自動化 › **AI 操作** の「AI からのアプリ操作を許可」を ON にするまで、`z2-ui`（`status` を除く）はすべて `error:"disabled"` を返します。`z2-action` の許可とは別のスイッチです。

### 5.2 アプリごとの段階

コマンド一覧 › 自動化 › AI 操作 の **アプリごとの許可** で決めます。「+ アプリを追加」で選んだアプリは `ask`（毎回確認）から始まります。コマンドでは次のように書きます。

```
z2-ui allow org.example.notes auto
z2-ui allow org.example.shop ask
z2-ui allow '*' look              # 一覧に無いアプリ
z2-ui allow org.example.notes default   # 一覧から外す
```

`z2-ui allow`（引数なし）は `z2-ui status` と同じ JSON を返します。

| 段階 | 読む | 操作する |
|---|---|---|
| `off` | ✕ | ✕ |
| `look` | ○ | ✕（`error:"read_only"`） |
| `ask` | ○ | 1 手ごとに通知で承認（「許可」「拒否」） |
| `auto` | ○ | そのまま実行 |

- 一覧に無いアプリは `*` の行に従います。`*` の既定は `look` です。
- **z2term 自身の画面、Android の設定・インストーラー、通知欄・クイック設定（システム UI）は常に `off` 扱いです。** AI がこの許可やユーザー補助の設定を変えたり、通知欄を開いて承認ボタンを自分で押したりできないようにするためです。
- **許可の設定は、アプリの内部（ターミナルから見えない場所）に保存します。** AI はターミナルで root として動くので、`~/.z2term/` の下に置いたファイルは AI が自分で書き換えられてしまうからです。テキストを正本にする方針（[AUTOMATION-ROADMAP](AUTOMATION-ROADMAP.md)）の例外です。
- `z2-ui allow <パッケージ名> <段階>` で許可を変えることもできます。ただし、許可を**広げる**変更（`look` → `ask` など）は、通知で人が承認したときだけ反映します。狭める変更はそのまま反映します。

**まとめて許可:** `ask` の承認通知には「許可」「拒否」に加えて **「このあと N 分は許可」** を付けます。押すと、そのアプリへの操作は N 分間、確認なしで進みます。

- N は コマンド一覧 › 自動化 › AI 操作 › **まとめて許可する時間** で決めます。1〜60 分、既定は 5 分です。ボタンの表示も設定した時間に合わせます（例:「このあと 10 分は許可」）。
- 許可はアプリごとです。別のアプリへ移ったら、そのアプリでまた確認します。
- まとめて許可している間は、常駐通知に残り時間を出します（例:「確認なし 残り 4 分」）。一時停止・停止を押すと、残り時間も取り消します。
- この時間の変更も、`z2-ui allow` と同じく、延ばす変更は通知での承認が要ります。
- 「送信」「購入」などのボタンを文字で見分けて止める方式は採りません。言葉の一覧では漏れが防げないからです。危険なアプリは、アプリ単位で `ask` にします。

`ask` の通知には、何をするか（例:「org.example.shop の『注文を確定』を押す」「検索欄に『…』を入れる」）を書きます。承認を待つのは最大 60 秒で、過ぎたら `error:"denied"` を返します。

### 5.3 中断と指示（AI への割り込み）

AI の操作中は、対象アプリが前面にあり、z2term は裏にいます（§8）。そのため、人は AI が動いているタブに文字を打てません。そこで、**常駐通知を AI への連絡口**にします。

AI の操作が続いている間は、常駐通知「AI がアプリを操作中（org.example.app）」を出し、次の 3 つを付けます。

| 通知の操作 | 動き | AI が受け取るもの |
|---|---|---|
| **一時停止** | 実行中の 1 手を止め、以後の操作を保留する | 次の `z2-ui` の呼び出しで `{"ok":false,"error":"paused"}`。「再開」が押されるまで、操作は同じ応答を返す。`look` は通る |
| **指示を送る**（通知の返信欄） | 実行中の 1 手を止め、入力した文を AI に渡す | 次の呼び出しで `{"ok":false,"error":"interrupted","message":"<入力した文>"}`。渡すのは 1 回だけで、その次の呼び出しからは通常に戻る |
| **停止** | 実行中の 1 手を止め、「AI からのアプリ操作」を OFF に戻す | `{"ok":false,"error":"stopped"}`。人が設定で ON にし直すまで続く |

- AI は数秒おきに `z2-ui` を呼ぶので、割り込みはその呼び出しへの返事として届きます。AI 側に特別な仕組みは要りません。`z2-ui --help` で「`interrupted` を受けたら、`message` を利用者からの新しい指示として読む」「`stopped` を受けたら作業を終える」と案内します。
- 返事は「次に呼ばれたとき」に届くので、AI が考えている最中の数秒は待つことになります。その間も、実行中の 1 手は押した時点で止まります。
- 指示は `~/.z2term/events.jsonl` にも `ui_interrupt` として 1 行書きます。マクロや `z2-when` からも拾えます。
- 一時停止・指示・停止は `z2-ui pause` / `z2-ui say "文"` / `z2-ui stop` でも実行できます。エッジパネルやタイルに置けば、通知を開かずに押せます。
- ⚠ **再開はコマンドに置きません。** 通知の「再開」と、設定タブの「再開」だけです。AI が自分で一時停止を解けないようにするためです。
- 画面の消灯・ロックで、実行中の 1 手は止まります（`z2-action` と同じ）。

### 5.4 記録

`~/.z2term/ui/log.jsonl` に、操作ごとに 1 行を書きます（時刻・アプリ・操作・対象の要素・結果・かかった時間 `ms`）。時刻は終わったときなので、前の行との間隔から `ms` を引いた残りが、呼び出しの外（AI が考えていた時間など）です（1.0.46）。`type` で入れた文字は記録せず、文字数だけを残します。`look` の中身も記録しません。

## 6. AI とのつなぎ方

| つなぎ方 | 使い方 |
|---|---|
| z2term の中で動く AI | シェルコマンドとして `z2-ui …` を呼ぶ |
| PC の AI | `ssh <スマホ> z2-ui …` |
| MCP 対応の AI | `z2-ui mcp` が標準入出力で MCP のやり取りを受け、§4 のコマンドを道具として見せる。PC からは `ssh <スマホ> z2-ui mcp` を MCP サーバー（標準入出力で動くもの）として登録する |

- MCP のやり取りは、JSON を 1 行ずつ受け渡すだけの取り決めなので、外部ライブラリを使わずに書きました。ライセンスの追加はありません。
- 道具の名前は `front` / `look` / `shot` / `tap` / `long` / `type` / `enter` / `key` / `open` / `wait` / `wait_change` / `scroll` / `swipe` / `notes` / `write_notes` / `mark` / `save` / `notifications` / `press_notification` / `status` / `guide` です。中身は CLI と同じで、同じ判定・承認・記録を通ります。一時停止・指示・停止と許可の変更は、道具には置きません（人が使うもののため）。
- `shot` は画像も一緒に返します（画像を読める AI はそのまま見られます）。会話に入る量を抑えるため、既定の縮小は 0.5 です。
- **AI 向けのガイドは `z2-ui --help`（引数なしも同じ）です（1.0.33）。** z2-ui は AI のための命令なので、ヘルプは人向けの短い説明ではなく、AI が読むための詳しいガイド（英語）にしました。全命令の引数と上限・JSON の項目・エラーコードごとの次の手・振る舞いの約束（`interrupted` を最優先する、断られた操作を繰り返さない、許可を回り道しない、取り消せない操作は利用者の明示の指示があるときだけ）を載せています。AI は知らないコマンドにまず `--help` を打つので、指示ファイルに何も書いていなくても見つけやすくなります。
- 人が打っても同じ文面が出るので、AI に何を教えているかを確かめられます。日本語で中身を確かめたいときは、AI に「`z2-ui --help` を日本語で要約して」と頼んでください。仕様の正本はこの文書で、ガイドはここから AI 向けに書き起こしたものです。命令を足してガイドに書き忘れると、テスト（`UiBridgeGuideTest`）が落ちます。
- MCP でつないだときは、接続したときの説明（`instructions`）と `guide` 道具で、同じガイドを渡します。

## 7. アプリの仕様を AI がどう知るか

AI は、アプリの仕様書なしで操作を始められます。人が初めてのアプリを使うときと同じく、画面のボタンの文字・説明・種類から意味を読み取ります。ただし毎回手探りでは遅く、誤操作もしやすいので、**一度分かったことを残して次回に使う**仕組みを用意します。

| 段階 | 仕組み |
|---|---|
| 初回 | AI が `look` → 操作 → `look` を繰り返して、画面を探りながら進む |
| 覚え書き | 分かったことを AI が `z2-ui note <パッケージ名> 文字`（`-` で標準入力から）で `~/.z2term/ui/notes/<パッケージ名>.md` に書く（例: 「検索は右上の虫眼鏡 `id=…/search`」「設定は ⋮ → 設定」）。1 行目に書いた時点のアプリの版が入る。読むのは `z2-ui notes <パッケージ名>`。`look` の出力の `notes` に、覚え書きがあるか（`exists`）と、いまの版のものか（`current`）が入る |
| 手順化 | `z2-ui mark` で区切ってから操作し、`z2-ui save NAME` で、その間に成功した操作を `z2-action` の定義として保存する。以後は AI を通さず、タイル・パネル・`z2-when` から再生できる |

- 覚え書きと保存した手順は、どちらもプレーンテキストです。人も読めて直せます。
- アプリが更新されたら（版が変わったら）、`look` の出力で「覚え書きは旧版のもの」と知らせます。AI はそれを前提に、確かめながら使います。
- 要素 ID（`id=`）は、表示文字よりもアプリの更新に強い目印です。覚え書きには、なるべく ID を書くよう MCP の説明で案内します。

**手順として保存するときの約束（`save`）:**

- `#N` で押した要素は、再生のときには番号が通じないので、要素 ID → 表示文字 → 説明 → 座標の順に置き換えます。切り詰めた表示文字（末尾が「…」）は元の表示と一致しないので使いません。
- 操作の間は、実際にかかった間隔（最大 2 秒）を `wait` で待ちます。
- `drag` は画面操作の「点を順になぞる」（`drag px`）として保存し、同じ速さで再生します（1.0.35）。
- **z2-action に同じ命令が無い操作（文字入力・確定キー・スクロール・画面の変化待ち・URI を開く・通知のボタン）を含む区間は、保存を断ります**（`unsupported_step`）。黙って落として保存すると、再生したときに途中が抜けた別の手順になるためです。`mark` で区切り直してから記録します。
- 同じ名前のマクロがあるときは上書きせずに断ります（`exists`）。利用者が作ったマクロを AI が消さないためです。
- 記録はメモリだけに持ちます。z2term を落とす・通知の「停止」で消えます。読むだけの操作（`look` など）は記録しません。

## 8. バックグラウンドでの操作

**基本の形: z2term は裏、対象アプリは前面。**

```
画面（前面）: 対象アプリ ← AI が押している様子がそのまま見える
裏          : z2term（AI のタブ・z2-ui の受付・ユーザー補助）が動き続ける
通知        : 「AI がアプリを操作中」＋ 一時停止 / 指示を送る / 停止（§5.3）
```

- z2term とその中の AI は裏でも動き続けます。`z2-ui open` で対象アプリを前面に出し、以後はそのアプリを操作します。画面分割は使いません。
- 人は、AI が押している様子を対象アプリの画面で見られます。口を挟むときは通知から行います（§5.3）。
- 作業が終わっても、z2term を自動で前面には戻しません。人が見ていた画面を勝手に切り替えないためです。戻したいときは、AI が `z2-ui open` で z2term を指定します。

**対象アプリ自体を裏に置いたまま操作することはできません。** ユーザー補助で読めて押せるのは、いま画面に表示されている窓だけです。Android は裏に回ったアプリの画面を描画しないので、裏のアプリのボタンは存在しません。これは Android の仕組みによる制約です。画面に出さずに済む操作には、次の手段を使います。

| 手段 | 範囲 |
|---|---|
| Intent・共有・URI（`z2-ui open` の一部） | アプリが受け付けている操作だけ |
| 通知のボタン（「返信」「既読」など） | 通知に出ている操作だけ。`z2-ui noti list` で一覧（段階が `look` 以上のアプリの通知だけ）、`z2-ui noti press <key> <ボタン名> [返信]` で押す。押すのは操作として扱う（段階・承認の対象）。z2term 自身の通知（承認の通知など）は一覧にも出さない |
| メディア操作（`z2-media`） | 再生関係だけ |
| 仮想画面（root 端末だけ） | 画面に出ない仮想の画面で対象アプリを起動して操作する。アプリを別の画面で起動できるのは root 権限があるときだけ。調査が必要 |

仮想画面は、第 3 段以降の調査事項にします。

## 9. 制限

- 要素を公開しない画面（ゲーム、独自に描画するアプリ）では、`shot` で撮った画像を AI が読み、`tap @X,Y`・`swipe` の座標で操作するしかありません。精度は AI の画像読み取りの能力に依存します。
- WebView（アプリ内に埋め込まれたブラウザー画面）は、アプリや OS の版によって要素の取れ方が変わります。
- Google Play では、ユーザー補助を自動操作に使う場合、用途の申告と審査が必要です。F-Droid 版には影響しません。
- 1 回の `look` は、既存と同じ 1.5 秒の探索時間の枠に収めます。要素が多い画面では `--in` で範囲を絞ります。
- `z2-ui` の安全装置は、AI が `z2-ui` を通る限りで効きます（§5 の冒頭）。

## 11. 決定事項（2026-10-18）

- 一覧に無いアプリの既定（`*`）は `look`（読むだけ）。
- 入力欄の中身は `look` で返す（パスワード欄は除く）。
- コマンド名は `z2-ui`。
- 操作中は z2term を裏、対象アプリを前面にする。画面分割は使わない。
- `ask` の承認通知に「このあと N 分は許可」を付ける。N は設定で 1〜60 分（既定 5 分）。
