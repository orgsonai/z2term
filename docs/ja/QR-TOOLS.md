# QRツールと自前の中継

対象: 0.8.604-alpha（versionCode 612）

## QRの読み取りと表示

**⚙設定 →「QRツール」→「QRツールを開く」**でカメラ・画像から読み取れます。端末で `z2-qr` と打つと、カメラで読み取る状態で開きます。`z2-qr` はクイック設定のタイル（`z2-tile set 1 z2-qr`）やエッジパネルに割り当てられます。画像内に複数のQRが見つかれば内容を選びます。カメラ権限は使用時だけ求め、画像の読み取りには不要です。画像は端末内で処理し、Linuxや別のバーコードアプリは不要です。

入口は0.8.597でコマンド一覧の上端、0.8.601でスニペット・接続先の見出しに置いていましたが、0.8.602で⚙設定と `z2-qr` に移しました。コマンド一覧の上端は取っ手だけで、タップすると閉じます。

**履歴（0.8.603）**: 読み取った内容はQRツールの下に履歴として残ります。タップで内容欄に表示し直し、長押しでピン留め・削除できます。「すべて消す」はピン留めしたものを残します。ピン留めしていないものは新しい順に50件までです。残すのはカメラ・画像・他アプリからの共有で読み取った内容だけで、「QRを表示」で作った内容や、履歴から表示し直した内容は足しません。履歴はこの端末だけに保存し、Wi-Fiのパスワードなども含みます。アプリロック中は表示しません。

**他アプリから渡す**: 写真・スクリーンショットの「共有」で **z2term — QR** を選ぶと、画像からQRを読み取ります。別のカメラ・QR読み取りアプリが表示したURLやテキストも、「共有」から同じ宛先へ渡せます。共有機能がない場合はコピーしてQR画面へ貼り付けてください。従来の「z2term」宛ての端末入力・ファイル取り込みとは別の共有先です。

一度に画像8枚まで、テキスト4,096文字まで受け取れます。画像に添えられた説明文やURLをQRの内容として扱わず、画像を優先して解析します。複数の結果は選択画面に表示します。共有元への一時読み取り権限を使い、画像を受信箱へコピーしたり、共有による自動化ルールへ内容を渡したりしません。アプリロック解除後に解析し、URLの自動オープンやコマンドの自動入力・実行は行いません。

対応形式のSSH・名前付きコマンドQRは、他のカメラアプリの「開く」からも確認画面に渡せます。HTTP/HTTPSは外部アプリの「共有」を使います。

内容を確認して、次の操作を選びます。読み取っただけでは実行・接続しません。開けるものは、中身に合った「開く」ボタンを押したときだけ対応するアプリの画面を開きます（0.8.602）。

| 内容 | 操作 |
|---|---|
| HTTP / HTTPS URL | 開く（LINEのログイン用URLなど、受け付けるアプリがあればそのアプリ、無ければブラウザー）、コピー、QR表示 |
| アプリ用リンク（`line://` など `//` 付き、`geo:` など） | 開く（受け付けるアプリで開く）、コピー、QR表示 |
| 電話番号（`tel:`） | 電話の画面を開く（発信はしない） |
| メール（`mailto:`・MATMSG） | メールを作成 |
| SMS（`sms:`・`smsto:`・SMSTO） | SMSを作成 |
| Wi-Fi（`WIFI:`） | Wi-Fiに接続（Android 11以上のWPA/WPA2・WPA3・パスワードなし。Android 10やWEPなどはWi-Fi設定を開き、パスワードをコピー） |
| 連絡先（vCard・MECARD） | 連絡先に追加（追加画面で確認してから保存） |
| 予定（iCalendarのVEVENT） | 予定に追加（追加画面で確認してから保存） |
| SSH接続先 | ホスト・ポート・ユーザー名を新しい接続先として保存 |
| 短い1行のコマンド | 端末へ入力、コマンド一覧へ保存、エッジへ追加、名前付きQR作成 |
| その他のテキスト | コピー、QR表示。改行・制御文字入りは端末へ入力しない |

`javascript:`・`file:`・`content:`・`data:`・`intent:` などのリンクは開きません。`//` の無い `語:値` の形（例 `Order:123`）はテキストとして扱います。開けるアプリが無い場合は画面に表示します。

端末への入力はEnterを送りません。実行する前に内容を確認してください。エッジへの追加は新しい非表示パネルを作成します。パネル管理から表示し、既存の設定は上書きしません。参照先のスクリプト・画像・メモ本文・パネル全体は含みません。

保存済みSSH接続先・1行のコマンドには**QR**ボタンがあります。接続先の操作ボタンはSSH、SFTP、追加サービス、QRの順で、QRは一番末尾にあります。通常のエッジ実行ボタンの編集にも**コマンド用QRを作成**があります。状態ボタン・トグル・アプリ起動ボタンの複合設定は対象外です。

SSHは `ssh://demo@host.example:2222` 形式で、ユーザー名は省略可能、IPv6は角括弧付きです。パスワード・秘密鍵・初期コマンド・踏み台・転送設定を含めません。取り込み後に必要な認証・経路を編集し、接続時にホスト鍵を確認します。

名前付きコマンドは `z2term://command?name=...&text=...` 形式（UTF-8 URLエンコード）です。未知・重複項目、改行・制御文字入りコマンドは拒否します。

生成上限はUTF-8で2,000バイト、内容欄は4,096文字です。長すぎる場合は内容を短くしてください。

## 自前の中継でファイル共有

**コマンド一覧 → サーバータブの一番下 → 中継してファイル共有**を開きます。自前のサーバーを用意した場合だけ使う機能です。外部中継サービスへの自動接続、端末の公開アドレスを使う直接共有はありません。

必要なものは、端末から接続できるSSHサーバーと、そのサーバー上の内部ポートへ転送する公開HTTPS URLです。SSHだけではブラウザー用のURLは発行されません。以下は同じサーバー上でHTTPSを終端する構成例です。

```text
受信者のブラウザー → HTTPS → 自前サーバーのリバースプロキシ
                                    ↓ 127.0.0.1:8080
                               SSHリモート転送
                                    ↓
                        Androidの共有用loopbackサーバー
```

### サーバーを用意する

1. 公開ホスト名（例 `share.example`）のDNSを自前サーバーへ向け、ブラウザーとAndroidが信頼する証明書を用意します。外部からHTTPSポートへ到達できるようにします。
2. SSHアカウントでリモート転送を許可します。内部待受は `127.0.0.1:8080` を例にしています。既存の設定に合わせて未使用の1024〜65535のポートを選んでください。
3. HTTPSの `/share/` をその内部ポートに転送します。

SSHサーバーの設定例です。`share-user` は利用するアカウントに置き換えます。既存アカウントに適用する場合、他用途の転送制限にも影響するので現在の設定に合わせてください。設定の検査後に再読み込みします。

```text
Match User share-user
    AllowTcpForwarding remote
    GatewayPorts no
    PermitListen 127.0.0.1:8080
```

`DisableForwarding` や `authorized_keys` の転送禁止も確認します。踏み台を使う場合、その踏み台には次のSSH接続先への転送許可も必要です。[OpenSSH設定資料](https://man.openbsd.org/sshd_config#AllowTcpForwarding)。

nginxのHTTPS仮想ホスト例です。証明書のパスは実際のものに置き換えてください。既存のHTTPS仮想ホストを使う場合は `location /share/` 部分を追加します。

```nginx
server {
    listen 443 ssl;
    server_name share.example;
    ssl_certificate /etc/ssl/share/fullchain.pem;
    ssl_certificate_key /etc/ssl/share/private.key;
    access_log off;

    location /share/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 90s;
    }
    location / { return 404; }
}
```

`proxy_pass` の末尾にはパスを追加せず、元の `/share/...` を保持します。共有URLをログに残さない構成にします。Origin、Cookie、Set-Cookieを削除・書き換えたり、アプリが返すReferrer-Policyを上書きしたりしないでください。設定を検査して再読み込みします。動作と設定形式は[nginxのproxy_pass資料](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_pass)を参照してください。共有停止中は転送先がないので、このパスは利用できません。

### アプリの設定と受信

1. SSHタブに接続先を保存し、一度接続してホスト鍵を確認します。共有では未確認・変更された鍵を自動承認しません。
2. 「中継してファイル共有」で、そのSSH接続先を選びます。既存の認証情報と踏み台を使います。初期コマンド・通常のポート転送・常駐トンネルは適用しません。
3. 公開HTTPS URL（例 `https://share.example`、パスなし）とサーバー側の内部待受ポート（例 `8080`）を入力し、設定を保存します。HTTPSの公開ポートと内部ポートは別のものです。
4. 期間を5・15・60分から選び、ファイルまたはフォルダを選びます。送信用コピー・SSH転送・公開URLの疎通確認が完了するとQRとリンクを表示します。期間はこの時点から数えます。
5. 相手はブラウザーでリンクを開き、必要なファイルを選んで「受信して保存」を押します。フォルダは階層を閲覧してファイルごとに保存します。

端末への外部からの着信やルーターの自動設定は使いません。HTTPSは自前サーバーで終端するので、ファイルはそのサーバーを通ります。端末からの疎通確認は相手の回線からの到達を保証しないため、用意した公開URLを別回線でも確認してください。

保存する共有設定はSSH接続先のID・公開URL・内部ポートです。SSHの認証情報は既存のSSH設定で管理します。設定しただけでは接続せず、共有開始時だけ接続します。接続失敗後の自動再開や、アプリ起動時の自動公開はありません。

### 共有の範囲と停止

1回に1ファイルまたは1フォルダ、合計最大1 GiB、フォルダはルートを含む1万項目・ルート下64階層までです。選択範囲と同容量に加え16 MiB以上の空き容量が必要です。読み取り失敗や上限超過があれば公開せず、途中のコピーを削除します。空フォルダ・異なる階層の同名ファイルを保持し、開始後の元ファイル変更は配信コピーへ反映しません。

期間中はリンクを知る人が受信できます。256ビットのランダムトークン、ファイルごとの確認後のCookie、キャッシュ抑止を使います。任意の端末内パスは公開せず、選択ルートの外へは移動できません。ファイルごとの受信確認は他のファイルには使えません。停滞接続は約30〜35秒で閉じます。

画面を閉じても共有は続き、通知から戻れます。保存完了まで端末をオンラインにしてください。共有停止・期限切れ・回線切り替え・切断で、その共有の中継・待受・転送中の接続を閉じ、コピーを削除します。他のサーバーは停止しません。接続準備は約2分で打ち切ります。中継の疎通が失われるとQRを隠し、復旧しなければ停止します。強制終了で残ったコピーは次回共有開始時に削除し、再公開しません。

## 検証

0.8.600の検証（2026-09-14）: PCでdebug・release・AndroidテストAPKをビルドし、単体テスト1,174件中1,172件成功・2件スキップ、lintエラー0件を確認しました。PCのloopbackに一時SSHサーバーとHTTPSプロキシを用意し、AndroidからUSBの検証用経路でSSHリモート転送を接続しました。PCの実ブラウザーで1 MiBを保存し、SHA-256一致、Range、受信確認前・不正Originの拒否、停止後の接続終了を確認しました。未知のSSHホスト鍵と使用中のリモートポートも拒否しました。テスト証明書だけをテスト用クライアントで信頼し、製品のTLS検証は変更していません。この試験は公開インターネット上の利用者サーバーへの到達性を検証するものではありません。

SSHホスト鍵を保存するときのBase64二重変換も修正しました。以前保存した鍵で照合に失敗する場合は、SSHタブで接続し、サーバー側の指紋と照合して再確認してください。共有から未知・変更された鍵を承認することはありません。

設定の制約、受信確認、範囲取得、フォルダ階層、コピーの上限と削除、期限切れ・停止を単体テストで検証します。Androidテストはファイル・フォルダの読み取り権限と中継設定の引き渡しを確認します。実ブラウザーのフォームPOSTで正しいOriginが送られるための `Referrer-Policy: same-origin` を維持します。

自前の公開環境で再試験する場合、PCにブラウザーと対応するWebDriverを用意し、端末へdebug版・AndroidテストAPKを入れます。debug版でSSH接続先を保存してホスト鍵を確認し、HTTPS転送先を用意してから `scripts/test-share-relay.py` に `--serial`、`--profile`（SSH接続先ID）、`--origin`（HTTPS origin）、`--remote-port` を渡します。端末は携帯回線、受信PCは別回線で試します。接続先を省略した実行はできません。試験は生成した1 MiBだけを共有し、単体・フォルダの受信、ハッシュ、実ブラウザーの保存、停止を確認します。実行するまで、利用者の公開サーバー経由の到達性は未検証です。
