# QRツールと端末からのファイル共有

0.8.597-alpha・ビルド未検証。QRカメラ、HTTPS、別回線からの受信、消灯中の転送は実機未確認です。

## QRの読み取りと表示

**コマンド一覧の最上部左側 → QR**でカメラ・画像から読み取れます。画像内に複数のQRが見つかれば内容を選びます。カメラ権限は使用時だけ求め、画像の読み取りには不要です。画像は端末内で処理し、Linuxや別のバーコードアプリは不要です。

入口はタブ共通の固定行にあり、左にQR、中央に取っ手、右に閉じるボタンを配置します。スクロール中やSSH・サーバー・自動化タブからも同じ位置で開けます。

**他アプリから渡す**: 写真・スクリーンショットの「共有」で **z2term — QR** を選ぶと、画像からQRを読み取ります。別のカメラ・QR読み取りアプリが表示したURLやテキストも、「共有」から同じ宛先へ渡せます。共有機能がない場合はコピーしてQR画面へ貼り付けてください。従来の「z2term」宛ての端末入力・ファイル取り込みとは別の共有先です。

一度に画像8枚まで、テキスト4,096文字まで受け取れます。画像に添えられた説明文やURLをQRの内容として扱わず、画像を優先して解析します。複数の結果は選択画面に表示します。共有元への一時読み取り権限を使い、画像を受信箱へコピーしたり、共有による自動化ルールへ内容を渡したりしません。アプリロック解除後に解析し、URLの自動オープンやコマンドの自動入力・実行は行いません。

対応形式のSSH・名前付きコマンドQRは、他のカメラアプリの「開く」からも確認画面に渡せます。HTTP/HTTPSは外部アプリの「共有」を使います。

内容を確認して、次の操作を選びます。読み取っただけでは実行・接続しません。

| 内容 | 操作 |
|---|---|
| HTTP / HTTPS URL | ブラウザーで開く、コピー、QR表示 |
| SSH接続先 | ホスト・ポート・ユーザー名を新しい接続先として保存 |
| 短い1行のコマンド | 端末へ入力、コマンド一覧へ保存、エッジへ追加、名前付きQR作成 |
| その他のテキスト | コピー、QR表示。改行・制御文字入りは端末へ入力しない |

端末への入力はEnterを送りません。実行する前に内容を確認してください。エッジへの追加は新しい非表示パネルを作成します。パネル管理から表示し、既存の設定は上書きしません。参照先のスクリプト・画像・メモ本文・パネル全体は含みません。

保存済みSSH接続先・1行のコマンドには**QR**ボタンがあります。通常のエッジ実行ボタンの編集にも**コマンド用QRを作成**があります。状態ボタン・トグル・アプリ起動ボタンの複合設定は対象外です。

SSHは `ssh://demo@host.example:2222` 形式で、ユーザー名は省略可能、IPv6は角括弧付きです。パスワード・秘密鍵・初期コマンド・踏み台・転送設定を含めません。取り込み後に必要な認証・経路を編集し、接続時にホスト鍵を確認します。

名前付きコマンドは `z2term://command?name=...&text=...` 形式（UTF-8 URLエンコード）です。未知・重複項目、改行・制御文字入りコマンドは拒否します。

生成上限はUTF-8で2,000バイト、内容欄は4,096文字です。長すぎる場合は内容を短くしてください。

## ファイル共有の操作

送信側の端末へインターネットから接続できる環境がある場合、相手は別回線からブラウザーだけで受信できます。受信側のアプリ・アカウント登録は不要です。転送クラウド・中継サービス・Bluetoothは使いません。

**コマンド一覧 → サーバー → この端末からファイル共有**を開きます。

既定は**自動**です。

1. 必要なら期間を5・15・60分から選びます（既定15分）。
2. 単体なら**ファイルを選んで共有開始**、フォルダなら**フォルダを選んで共有開始**を押して選びます。
3. 接続中のWi-Fiまたは携帯回線のアドレスを取得し、空きポートで共有用サーバーを起動します。送信用コピーの準備後、URL・QRを表示します。遠隔の相手にはリンクやQRの画像を渡します。

自動は**HTTP（暗号化なし）**です。画面にその旨を表示します。HTTPSを使う場合や、ルーターでポート転送を設定している場合は**手動**へ切り替えます。

手動の操作:

1. **公開URL**に相手が開くアドレスを入力します。例: `https://share.example:8443`。パスは付けません。
2. **待受ポート**は1024〜65535の未使用ポートにします。ルーター外側のポートと違っていて構いません。
3. 期間を5・15・60分から選びます。
4. HTTPSなら、公開ホスト名に一致する証明書・秘密鍵・証明書チェーン入りのPKCS#12（.p12/.pfx）とパスワードを指定します。ブラウザーが信頼する証明書を使えば受信者の追加設定は不要です。証明書の自動取得はしません。
5. HTTPなら、ファイルとURLが暗号化されないことを画面で確認して選択します。
6. **ファイルを選ぶ**または**フォルダを選ぶ → 共有開始・QR表示**。送信用コピーの準備後、QRとリンクを表示します。遠隔の相手にはリンクやQRの画像を渡します。

受信者はQR・リンクをブラウザーで開きます。フォルダ共有では階層一覧からフォルダを開き、必要なファイルを選びます。上部の親フォルダへのリンクは選択されたルートまで戻れます。ファイルの名前と容量を確認して**受信して保存**を押すと、そのファイルだけをダウンロードします。フォルダを閲覧するだけではファイル本体を送りません。受信ページは日本語・英語です。

選択したフォルダの下をすべて準備してからURLを表示します。空フォルダも表示し、別の階層にある同名ファイルは区別します。共有開始後に元ファイルを変更しても配信するコピーは変わりません。受信側で階層を丸ごと保存する操作ではなく、必要なファイルをブラウザーの保存先へ個別に保存します。

手動で指定した公開URLと待受ポートだけを保存します。自動取得したアドレス・ポートで手動設定を上書きしません。証明書は共有ごとに選択し、パスワードは保存しません。1回に1ファイルまたは1フォルダを選択でき、合計最大1 GiBです。フォルダはルートを含む1万項目、ルートの下64階層まで。選択範囲と同容量のコピーに加え、16 MiB以上の空き容量が必要です。読み取れない項目・不完全な一覧・上限超過があれば共有全体の準備を終了し、途中までのコピーを削除します。フォルダはAndroidの選択画面でアクセスを許可できる範囲が対象です。

画面を閉じても共有は続き、通知から戻れます。保存完了までオンラインにしてください。共有停止・期限切れ・アプリの全部停止で共有用サーバーと転送中の接続を閉じ、コピーを削除します。共有画面・通知で共有を止めても、他のサーバーは停止しません。Wi-Fiと携帯回線の切り替え・切断でも共有を停止し、自動取得したアドレスが使えなくなった場合も停止します。再度ファイルまたはフォルダを選ぶと新しいURLで共有します。プロセス終了・再起動後は自動再開しません。強制終了で残ったコピーは次回開始時に削除し、再公開しません。

## 公開URLの条件

共有開始だけで回線の着信制限は解除されません。自動取得はAndroidが接続中として扱うネットワークの端末アドレスを使い、Wi-Fiから携帯回線へ勝手に切り替えません。公開IPv4が端末に割り当てられていれば優先し、次にネイティブのグローバルIPv6を使います。ローカル・CGNAT・特殊用途・使用不可のアドレスは候補から外します。外部のIP照会サービスやUPnPでのルーター設定変更は行いません。

Wi-Fiでも条件は同じです。ルーターのプライベートIPv4しか得られない場合は、公開URLを自動生成できません。グローバルIPv6があってもルーターの着信許可が必要です。自動取得できない場合は理由を表示し、回線変更または設定済み経路に合わせた手動指定へ案内します。

- **IPv4**: 公開IPv4と、必要に応じてTCPポート転送・着信許可が必要です。通信事業者のNAT配下ではルーターの設定だけで公開できない場合があります。
- **IPv6**: 端末のグローバルIPv6と着信許可が必要です。IPv6だけのURLには受信側もIPv6接続が必要です。
- **ホスト名**: DNSを正しい公開アドレスに向けます。手動の待受はIPv6/IPv4の両方を優先し、IPv6を明示したURL以外は必要ならIPv4へフォールバックします。
- 既存のHTMLサーバーと同じポートは同時に使えません。自動は空きポートをOSに割り当ててもらいます。手動はこの機能の待受ポートへ届くように設定します。

「外部からの接続は未確認」は端末で待受が始まった状態です。ページへのアクセスがあっても、アプリはアクセス元が別回線かを区別しません。別回線から実際に開けるか確認してください。配信量は再送を含み、保存完了の証明にはなりません。

期間中はリンクを知る人が受信できます。256ビットのランダムトークン、ファイルごとの確認後のCookie、キャッシュ抑止を使い、任意の端末内パスは公開しません。URLの数値IDは選択範囲の一覧内だけで解決します。選択フォルダの上には移動できず、あるファイルの受信Cookieで別ファイルをダウンロードすることもできません。停滞接続は約30〜35秒で閉じます。HTTPSはTLS 1.2/1.3です。

## 検証状況

受信確認前の拒否、確認後の保存、範囲取得、空ファイル、不正パス・Origin、期限切れ・停止、URL正規化、QR不正入力の単体テストを追加しました。自動アドレス選択・IPv6のURL形式・実ポートでの受信確認・停止による待受と既存接続の終了・別サーバーを停止しないことの回帰テストも追加しています。階層一覧・親リンク・空フォルダ・同名ファイル、個別受信・ファイル間の確認分離、不正ルート、コピー後の元ファイル変更、合計容量制限、読み取り失敗・中断時の削除の回帰テストも追加しています。フォルダ＋手動HTTPSで、選択範囲の権限と証明書の権限を別々に引き渡すAndroidテストも追加しました。スマホ上でビルド・テストは実行していません。

実機ではカメラ・画像（日本語・複数QR・権限拒否）、アプリロック復帰、読み取りだけでは実行されないことを確認します。共有は別回線からHTTP/HTTPSで受信し、保存ファイルと元ファイルのハッシュ、停止・期限切れ、消灯・回転・通知からの復帰を確認します。自動はファイル・フォルダ選択だけで開始すること、Wi-Fi／携帯回線の切り替え時の停止、公開アドレスなしの表示、手動設定が保持されることも確認します。HTTPSは通常のブラウザーの信頼・ホスト名検証を通る証明書で試します。

外部共有の追加確認: 写真・スクリーンショット・複数画像、読み取り済みURL、ClipDataだけの入力、不正URI・過大入力を扱うAndroidテスト6件を追加しました。実行は未実施です。実機では共有先の表示、ロック中の受信、回転後に二重処理しないこと、同じ受信画面への再共有も確認します。
