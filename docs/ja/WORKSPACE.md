# 表示先と Android の入出力

0.8.643-alpha（versionCode 651）。アプリはセッションの表示・入力配送と、Android の文書・選択文章の受け渡しを担当します。文章加工やファイル変換などの処理はユーザーのコマンド／マクロに置きます。新しい Android ライブラリ・外部コードの同梱はありません。

## 端末と GUI を並べる

1. 並べたい端末、ローカル GUI、VNC、RDP のタブを開きます。
2. ＋の隣にある **GUI（🖥）ボタンを長押し** し、**上下** または **左右**、もう一方のタブを選びます。
3. 枠の中をタップすると、その枠が入力先になります。最初のタップは入力先の切り替えだけを行います。緑の枠が入力先です。
4. 境界をドラッグして割合を調整します。**GUIボタン長押し → 1画面へ戻す** で解除できます。

GUIボタンを短く押すと従来どおりGUIを開きます。操作方法は **設定 → Tips** にもあります。分割中はGUI専用の外枠と余白を出さず、GUI／CUI間のフォーカス切り替えで表示領域の寸法を保ちます。キーボードの開閉状態も共通です。

タブ欄で別のタブを選ぶと、入力中の枠がそのタブに置き換わります。片方を閉じると、残っている選択中のタブを1画面で表示します。表示の変更で接続やシェルを終了しません。配置はアプリの実行中だけ保持します。

## 外部モニターとスマホを使い分ける

Android が独立した表示先として認識する画面を接続し、表示したいタブで **GUIボタン長押し → 外部画面名** を選びます。単なる画面ミラーリングしか提供しない機器では利用できません。

- 外部画面に表示した GUI のタブをスマホで選ぶと、スマホの表示領域が相対操作のタッチパッドになり、キーボードもその GUI に入力します。
- 端末を外部表示した場合も、スマホ側のキーボードから入力できます。
- スマホで別のタブに切り替えると、それぞれ別のセッションを表示・操作できます。
- **GUIボタン長押し → スマホへ戻す**、またはモニター切断でスマホに戻ります。接続は維持します。

同じセッションへスマホと外部画面が異なる寸法を送り続けないよう、表示先を一つに定めます。通常のリモート VNC の実画面サイズは変更せず、ローカル VNC／RDP は既存のリサイズ対応範囲に従います。アプリがバックグラウンドへ移った場合は外部表示を閉じ、戻った際に再表示します。アプリロック中は外部にもセッション内容を表示しません。

## ローカル GUI の直接表示（試験機能）

**設定 → GUI → ローカル GUI を直接表示** を ON にし、新しい GUI タブを開きます。設定の変更は動作中のタブには適用しません。端末コマンドから開く場合、既存の端末は起動時の方式を引き継ぐため、設定変更後は新しい端末を開いてください。

通常の Linux パッケージ導入経路で Xvfb と x11vnc を用意します（Arch は `xorg-server-xvfb`、Alpine／Debian 系は `xvfb`）。未導入の場合は、既存のダウンロード確認設定に従います。これらを APK に同梱する変更はありません。

- Xvfb の XWD フレームバッファをアプリが直接読み、Android の描画領域へ表示します。
- x11vnc は `-nofb` で起動し、既存の RFB 接続でキー・ポインター・テキストクリップボードだけを扱います。画像更新は要求しません。
- 解像度は起動時の表示領域と GUI 表示倍率で決まります。各辺最大4096、合計8,388,608画素。回転・枠の変更後は拡大縮小して表示し、解像度自体は変えません。
- 画面の読取りは表示中に最大20回／秒。非表示やアプリ停止中は読取りを休止します。
- GPU 高速化・ゼロコピー・従来方式より速いことは保証しません。端末ごとの描画負荷・電力測定は未実施です。既定は従来方式で、VNC／RDP 接続も従来のまま使えます。

## コマンドで Android のファイル選択を開く

```sh
# 選んだファイルを取り込み、シェルで読めるパスを受け取る
file=$(z2-file pick 'text/*') || exit
cat "$file"

# ローカルファイルの保存先を Android の画面で選ぶ
z2-file save "$HOME/result.txt" text/plain

z2-file --help
```

`pick` の MIME 型を省略すると全種類、`save` で省略すると `application/octet-stream` です。選んだ文書は `$HOME/z2term-inbox/` 以下へコピーされます。元の文書とは独立したファイルで、不要になったコピーはユーザーが削除できます。クラウド等は Android に提供元が登録されていれば選べます。

URI を偽の Linux パスとして返したり、共有元を無断で上書きしたりしません。`save` は新規文書の作成です。同名の扱いは Android の文書選択画面に従います。最大512 MiB、選択から転送まで5分以内、同時に1件。取り消し・失敗は非ゼロ終了です。Linux 未導入の Android 標準シェルでも使えます。バックグラウンドからの画面起動には Android の制限が適用されるため、端末画面を前面にして実行してください。

## 他のアプリの選択文章を加工して戻す

1. **コマンド一覧 → スニペット** で、任意のコマンドを登録します。例えば `tr '[:lower:]' '[:upper:]'` は英字を大文字にします。自作マクロも指定できます。
2. **選択した文章の処理に使う** を ON にします。入力フォームも併用できます。
3. 他のアプリで文章を選び、選択メニューの **z2termで加工** を選びます（メニューの続きにある場合もあります）。
4. コマンドを選び、結果を確認して **選択文を置き換える** を押します。

選択元が Android の文章処理連携（`ACTION_PROCESS_TEXT`）に対応している必要があります。読取専用の文章では結果の表示・コピーができ、置き換えボタンは表示しません。全アプリの選択欄を強制的に書き換える機能ではありません。

選択文章は、コマンド文字列へ埋め込まず**標準入力**で渡します。**標準出力**が結果です。改行・末尾改行・空の結果を保持します。処理時間は60秒、入力と結果は各64 KiBまで、入力の NUL は不可。入力フォームの値は既存の安全な引数展開を使います。エラー／取り消し時は元の選択を置き換えません。画面を開いただけでは実行しません。文章をどこへ送るか、何を保存するかは選んだコマンドの処理に従います。
