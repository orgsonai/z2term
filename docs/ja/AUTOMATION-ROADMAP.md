# Android 操作マクロの拡張案

2026-09-08。以下は提案であり、新しいコマンドはまだ実装していません。
既存の `z2-when`（トリガーと条件）、シェルマクロ、エッジパネルを共通の入口として使います。

| 優先 | 拡張 | できるようになること |
|---|---|---|
| 1 | 座標操作 | タップ・長押し・スワイプを座標と時間で指定。複数操作を順番に再生 |
| 1 | 実行管理 | 完了を待って次へ進む、取消・タイムアウトで停止、緊急停止、手順ごとの履歴 |
| 2 | ジェスチャー割り当て | 取っ手でのダブルタップ・上下スワイプなどに別々のコマンドを割り当て |
| 2 | 座標選択と編集 | 画面上で点や経路を選び、待機時間や繰り返しを編集してマクロへ保存 |
| 3 | UI要素の操作 | 座標の代わりに文字・説明・要素IDでクリック。要素が現れるまで待つ |
| 3 | 条件分岐 | 前面アプリ、要素の有無、成功・失敗に応じた分岐と回数制限付き再試行 |

最初は座標操作と実行管理を一緒に作ります。例えば「アプリ起動 → 待機 → 指定位置をタップ → スワイプ」を
既存マクロから呼べるようにします。`sleep` だけに依存する版から、後で「目的の要素が現れるまで待つ」へ進めます。

座標は画面左上を原点とするpx、または画面に対する百分率を明示します。記録時の画面サイズ・向きも保存し、
回転や対象アプリの不一致では停止します。百分率だけではアプリのレイアウト変更を吸収できません。
操作中は自分の板がタップを奪わないようにし、同時実行は1本、通知から停止できるようにします。

Androidのユーザー補助サービスには、座標に沿った操作を送る `dispatchGesture()` があります。
既存サービスへ `canPerformGestures` を追加する構成が候補です。完了・取消コールバックを必ず待ちます。
画面内容を読む許可は座標再生には不要ですが、UI要素を探す段階では別途必要になります。

ジェスチャー検出は、まず取っ手が受け取るタッチの範囲で増やします。全画面の自由な操作をそのまま録画する機能とは
区別します。ユーザー補助の `onGesture()` はタッチ探索モードが前提となり、通常のタッチ操作を変えるため、
単純に有効にすればよいものではありません。最初の記録機能は「点・経路を選ぶ方式」が現実的です。

GUIでの手順追加・並べ替え・条件編集を用意し、保存結果はテキストへ戻します。これにより、スマホだけで編集でき、
CLIや既存マクロとも共有できます。全面的な操作記録、画像認識、分割起動はそれぞれ別の検証課題です。

根拠: [ジェスチャー送信](https://developer.android.com/guide/topics/ui/accessibility/service)、
[AccessibilityService API](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)、
[タッチ探索の設定](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo)。
