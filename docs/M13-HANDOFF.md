## 1. 日本語かな漢字変換の長文対応（中心テーマ）

`KanaKanjiConverter` / `ComposingState`（`ui/terminal/keyboard/KanaKanjiConverter.kt`）と
候補バー（`TerminalScreen.kt` の `CandidateBar`）の改修。

### 1-1. 初版（`171163e`）— のち置き換え

- `segmentParts`（文節分割で各セグメントの読み・候補を返す）と `multiSegmentVariants`
  （4 文字以上のかなで「文節組み換えの複数候補」を生成）を追加。
- 問題: 組み換えバリエーションは **ほぼ使われない候補ばかり**で、長いかな全体が
  「ごちゃまぜ変換」として候補に並び、変換キーを押すまで使いにくかった（ユーザー指摘）。

### 1-2. 確定版（`01cf548`）

- **自動ブロック分割**: 辞書ブロックが 2 文節以上に分かれる長文は、変換キーを押さなくても
  かな打鍵だけで自動的に先頭ブロックへスプリットし、ブロック毎に予測する。
  - 判定は `segmentParts(text)` が非空（= 辞書ヒット 2 文節以上）かどうか。打ちかけの 1 語では
    分割しない（誤分割回避）。
  - `ComposingState.reevaluateAutoSplit()` を `emitKana` / `append` / `replaceLast` / `backspace`
    の後に呼ぶ。先頭ブロック長は変換キーと同じ `autoSplitHeadLen`。
  - 「自動分割」か「変換キーによる手動分割」かを `autoSplit` フラグで区別。
    **⌫ は自動分割中も素直に 1 文字削除**（手動分割中は従来どおり、まずスプリット取消）。
- **文まるごと一括予測**（`multiSegmentVariants` を廃止して置換）:
  - スプリット中で後続（tail）が残るとき、各ブロックの第1候補を連結した「文まるごと」候補
    （`segment(text)`）を `fullPrediction` に持ち、候補バーに **薄緑ピル**で 1 つ出す。
  - タップで `commitFull()` が全文を一括確定（composing をリセット）。
  - `convertFlexible` からは `multiSegmentVariants` の呼び出しと関数自体を削除。
- **未確定中のキー静音化**（`JapaneseFlickKeyboard.kt`）:
  - ◀▶・変換キーは未確定中に背景を緑（accent）にしていたが**静かに保つ**。
  - 緑にするのは「再変換」ヒント時（composing が空 ∧ `canReconvert`）の変換キーのみ。

### 1-3. 文節品質の修正（`5f9fd80`）

`01cf548` 直後にユーザー検証で「`きょうの → 今日の` すら出ない / ブロック予測が機能しない」と判明。
辞書ベース合成の 3 つの穴を修正:

- **`segment` を 1 文節以上で返す**（旧: 2 文節以上）。`今日`＋助詞`の`＝1 文節でも捨てず、
  漢字を含む ∧ reading と異なるなら返す → `きょうの → 今日の`。
- **助詞をかな残し**（`PARTICLES`）。`の`/`は`/`が`… は単漢字（野/葉/…）を持つため、文節結合で
  化けないよう単独時はかなのまま（`今日野` にしない）。
- **文末助動詞をかな残し**（`AUX_KANA`、長い順で前方一致消費）。`でしょう`→賞, `ました`→増田,
  `です`→鱒 等の化けを防ぐ（`如何でしょうか` を `如何で消化` にしない）。単独で `しょうか` を打って
  `消化` が欲しい場合は `convert` が直接出すので損は無い。
- **先頭ブロックを文節単位に**（`autoSplitHeadLen`）。内容語の後ろのひらがなを「次の内容語が
  始まるまで」取り込む → `あしたのてんき…` の先頭は `あしたの`（今日の/明日の）になる。

例: `あしたのてんきはいかがでしょうか` → ブロック **明日の / 天気は / 如何でしょうか**、
一括ピル = **明日の天気は如何でしょうか**。

### 1-4. 候補バーの並び（`CandidateBar`）

`[head ピル(生かな/スプリット頭)] [tail ラベル(残りかな)] [一括予測ピル(薄緑)] [ブロック候補…]`
オートスクロールの `base` に一括予測ピル分を加味済み。
